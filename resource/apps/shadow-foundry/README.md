# 影形铸坊 / Shadow Foundry

转动高低不同的金属工件和侧向灯光，让真实高度投出的地面阴影覆盖青色目标格，同时避开琥珀色禁区。改变灯向，阴影会向相反方向伸展；重叠阴影只计算一次。

这是 pureTV 百款游戏计划的第 42 款设计，包名 `com.ecojust.shadowfoundrytv`，版本 `0.1.0`。单人游玩，支持电视遥控器、键盘和局域网手机手柄。完成验证并推送后才计入完成数量。

## 操作

- 上或左：选择工件 WORK。下或右：选择灯光 LIGHT。
- A：顺时针旋转所选对象。工件每次转 90 度，灯光每次切换一个 45 度的罗盘方位。键盘使用 Space、Z、Enter；手机点击右侧上半区。
- B：逆时针旋转所选对象。键盘使用 X、B；手机点击右侧下半区。
- 方向与 A/B 按边沿生效，长按不连续旋转；松开再按或改变方向才执行下一步。A/B 同时按下优先 B。动作与方向同时按下时，会旋转原先选中的对象，方向不会排队。
- P、Escape、START 或独立暂停按钮：暂停/继续；R 或手机 SELECT：重试。菜单中的 B 切换声音。

手机右侧整个三分之一区域分为上下两半，避免寻找小按钮。暂停、输入取消或手柄断线之后，请先真实松开仍按住的按键，再进行新操作。重试恢复初始工件、灯向、调整次数与全部记录。

## 怎么通过

每局有 12 次调整机会。选择对象免费，每次顺时针或逆时针旋转消耗一次。覆盖全部目标格且没有阴影进入禁区时立即通关；第 12 次旋转若合格仍然通关，否则失败。没有提交按钮、撤销、次数返还或超时失败。

画面分别显示目标命中数、所需命中数、禁区命中数、允许命中数和剩余调整次数。仅有相同大小的阴影不代表合格，目标和禁区必须分别满足要求。

工件上的实心标记对应地面的空心定位点；先让两者重合，再观察高柱与阴影尖端的空心引导标记，调整灯光。定位点和尖端是可见提示，不代替阴影覆盖判定。完整平面图展示所有判定格，避免高工件挡住地面。

| 任务 | 目标格数 | 特点 |
| --- | ---: | --- |
| 西光落影 | 7 | 横向投影与两行重叠阴影 |
| 北光长脊 | 7 | 不同高度在纵向汇成连续长影 |
| 斜光交叠 | 11 | 斜向投影、闭边界采样与多重重叠 |

三个任务分别是一局独立谜题，禁区允许命中数均为 0。地面是 13×13 的有限采样板，以格中心是否在阴影内计数，不是连续阴影面积。阴影包含工件底面；格中心恰在阴影边缘也计入。灯光采用公开的平行投影规则，对角灯向的水平投影长度比正向更长，不宣称恒定仰角或真实点光源。

## 画面与公开规则

画面采用金属工坊、低模工件和烘焙材质，三个高度的工件与文字共用一个本地图集。阴影格按唯一并集绘制，轮廓读取模型的真实投影；中文说明使用 DOM。实际绘制次数、帧率、截图与画面审阅以发布报告为准。

- [公开设计](docs/public-design.md)：三个任务的完整几何、目标、禁区和手算规则。
- [模型规则](docs/model-contract.md)：投影、并集、调整预算、输入边沿与终局优先级。
- [观察接口](docs/public-interface.md)：可见反馈策略、宿主接入和真实观察记录的要求。

共享 Android 宿主负责手机手柄、暂停与毛玻璃弹窗。界面、连接生命周期与真机效果依据实际验证报告记录。

## 构建与验证

在仓库根目录运行 `python3 resource/game-kit/build.py --game resource/apps/shadow-foundry --output /tmp/shadow-foundry-build`。构建工具生成 `game-config.json` 和 `assets-index.json`；`game.json` 的 `actions: 2` 配置手机 A/B 上下触控区。

发布产物为 `shadow-foundry-0.1.0.apk` 和 `docs/gameplay-0.1.0.mp4`，每个文件都必须严格小于 10,000,000 字节。发布验证、签名、录制和画面审阅分别记录在 `docs/verification.json`、`docs/signing-receipt.json`、`docs/gameplay-0.1.0.json` 与 `docs/art-review.json`。

普通游玩记录需要三个任务各一次实际胜利与一次自然耗尽次数的失败，均使用正常输入。数学边界夹具必须单独标注，不能冒充可到达的游戏状态。浏览器截图和录像是稀疏观察，不能补造未记录的操作；软件渲染也不代表电视或手机真机性能。未做实体硬件测试时，报告须明确注明。
