# Frost Brake — public model contract

This is the complete accepted rules contract paired with public-design.md and public-interface.md. All numbers are public. No implementation, solver, private witness, preset route or test-only state injection is authorized by this document.

## State and constants

`PureModel.create(seed, difficulty)` returns a fresh playing state using the three explicit layouts in the design. Difficulty is a scenario index, not a change of physics; only integer0,1,2 is valid, otherwise select0. A seed is recorded only if it is an integer in [0,4294967295], otherwise record739; geometry is deterministic and does not depend on random generation. Initial x is the scenario start; v=0, damage=0, time=0, deliveries=0, dwell=0, score=0, phase=`playing`, failure=null. The three target widths are12,9,6; half-sled extent H=1.20; legal center range is [1.20,98.80]. Initial controls are ready, lastCancelEpoch=null. Initial lastInput/lastStep/terminalReceipt are null, events/deliveryReceipts empty and nextSeq=0. There is no energy, ammunition, random hazard, velocity cap or round expiry.

Constants: push P=2.40, base friction F=0.12, additional claw friction C=4.80, safe claw speed Vsafe=5, load coefficient K=12, damage limit Dmax=100, docking speed Vdock=0.30, docking dwell Tdock=0.60, stick threshold=0.35. Geometry and physical thresholds use mathematical real values; the numerical tolerances below only bound implementation error.

## Held-input and time semantics

Only input.x and held input.a affect forces. Missing, null, array or non-object input is treated as an empty input record; only the record's own properties are considered. Clamp finite numeric x to [−1,1], otherwise use0; axis=0 when |x|<0.35, else sign(x). Preserve raw validity separately from normalization. A is requested only when `a === true`. Ignore y, b, aPressed and bPressed for gameplay, including release acknowledgment. Thus edge pulses cannot cause forces that differ merely because calls were divided differently. Fields cancelEpoch and cancelled follow the explicit release gate below. Invalid input is neutral, but missing/invalid x or A cannot acknowledge real release.

A positive finite numeric dt requests that entire duration, provided state.time+dt is finite and strictly greater than state.time in the numeric representation. If that endpoint overflows or cannot represent any increase, classify the call as `nonrepresentable` and handle it as a semantic no-time sample. This explicit representation guard neither truncates nor defers time. Otherwise integrate until the duration is consumed or the first terminal event occurs. Do not silently clamp it to a frame, discard a nonterminal remainder, or interpret one call as one tick. Exact resting pieces must use stationary arithmetic, avoiding expressions such as zero times an overflowing squared duration. Host runtime.js happens to call step at1/60 s using a RAF accumulator, clamps measured RAF delta to0.1 s, and allows at most six substeps per RAF; those are host semantics, not model dt semantics. Host elapsed/tick are not the model's terminal clock. state.time is the canonical rounded absolute model timestamp; actual elapsed physical intervals are authoritative in ordered segment.duration values and lastStep.consumedDt.

Zero, negative, nonfinite, nonnumeric, omitted or nonrepresentable dt is a semantic no-time sample: it may update cancellation bookkeeping, lastInput, derived contact and the real-release gate, but advances no physics, time, damage, dwell or score and cannot deliver or lose. Its observation receipt has acceptedDt=consumedDt=unusedDt=0 and no physical segments. It does not secretly accumulate time for a later call. A terminal state ignores every subsequent step completely, preserving the entire final snapshot including events, receipts and lastStep.

For nonterminal calls, a nonnegative safe integer cancelEpoch is observed; an invalid/missing epoch leaves the previous one unchanged. The first observed epoch establishes a baseline. A change from an existing epoch, or cancelled===true, closes controlsReady and makes the whole call neutral (axis=0, claw=false), even if its raw sample also claims released controls. On a later noncancelled sample with an own finite numeric x in (−0.35,0.35) AND an own a===false, open controlsReady; that release sample remains neutral for its entire call. Both explicit raw conditions are required; y/B/pressed edges neither acknowledge nor prevent release. While closed, all other samples remain neutral. No-time samples may establish these semantic changes but cannot produce motion. Once ready, later noncancelled samples use their normalized held controls. Start/retry uses a fresh state; the shared host's first cancellation sample establishes its usual quarantine.

Cancellation never changes x, v, damage or dwell directly. A positive cancelled/blocked step still consumes real simulation time with ordinary ice drag and no active push/claw. Dock dwell continues or resets solely according to actual physical eligibility. Host pause calls no model steps and freezes the model clock; resuming does not erase inertia. The host already quarantines stale physical holds until real release; the model gate never treats synthetic cancelled neutral as that release.

## Exact piecewise law

Let u=P×axis. Let B be the frost-band index containing the center claw on the immediate forward-time side, or −1. Let E=(effective A && B>=0) and μ=F+(E?C:0).

For v≠0, acceleration is `a=u−μ sign(v)`. For v=0, acceleration is `sign(u) max(|u|−μ,0)`; zero u gives zero a. Integrate every constant-acceleration piece exactly: `x(h)=x0+v0 h+½a h²`, `v(h)=v0+a h`. Split at v=0 before changing the sign branch. Friction never numerically flips a stopped sled. With A held on frost, μ=4.92>P, so a stationary sled stays still. Outside frost, E=false regardless of A, making A/no-A dynamics literally identical for identical other commands.

Band interiors are spatially fixed closed intervals [l,r]. At a boundary with nonzero v, use the side entered by motion: at l, v>0 enters and v<0 leaves; at r, v<0 enters and v>0 leaves. At v=0 with effective A, inclusive contact engages static friction and the sled remains at rest. At v=0 without A, use the impending acceleration direction for the next moving interval; if it remains stationary use inclusive membership. Point contact has no duration, creates no impulse and causes no damage by itself. Every band entry/exit splits the exact motion; endpoint membership must never retroactively decide an entire crossing step. Reaching a band endpoint exactly at v=0, touching then reversing, ending a call there, or departing a resting endpoint uses this same forward-side law. These situations emit no separate band-enter/exit events: segment boundaries and contact observations contain the actual facts, avoiding duplicate movement events at a zero-duration touch or later call.

Cargo rate is `dD/dt = E ? K max(|v|−Vsafe,0) : 0`. Damage represents the active claw's high-speed load, not total acceleration, the raw A level, press count, direction reversal or one charge per engagement. Split at v=±5. Within an engaged piece entirely above speed5, speed has constant sign s and damage increment is `K[(|v0|−5)h + ½s a h²]`; otherwise the increment is zero. This remains nonnegative on the correctly split piece. There is no fixed engagement charge, cooldown, forgiveness or repair. Separate active episodes just contribute their actual integrals.

For active dock i=deliveries<3 with center c and full width w, the allowed center interval is [c−w/2+H,c+w/2−H]. Eligibility is full containment AND |v|<=0.30. Dwell rises at1 second/second on every actually consumed eligible open-time interval and becomes zero on any actually consumed ineligible open-time interval. An isolated eligible point contributes no dwell. Do not clear dwell at call-end merely because the hypothetical next interval under the old controls would be ineligible: the next real sample may prevent that departure. It is independent of whether A is held. At dwell=0.60, deliver exactly once, increment deliveries, emit and preserve its receipt, reset dwell=0, and immediately activate the next dock using unchanged x/v/damage/time. Continue the remaining call duration under the same effective held controls. The third delivery wins and stops integration immediately.

## Event partition and ties

At each piece, solve the earliest actual event time among the remaining call duration, spatial frost boundaries, v=0, v=±5, v=±0.30, active dock's allowed-center boundaries, an outward lane exit, docking completion, and damage exhaustion. Polynomial roots must lie on the current physical branch and within the remaining duration. Use the smallest future root; resolve the current boundary's forward side rather than rediscovering its zero root. Resting/straight pieces need no artificial microsteps. Never consume an invented epsilon of time to escape a boundary.

An edge loss occurs at the first outward crossing of the legal center interval, recorded at its boundary contact time, the infimum of the strictly-outside times. Reaching an edge with v=0 and then remaining there or moving inward is legal; starting on an edge and accelerating outward loses at time zero of that positive-duration call. A no-time call never triggers this forward-motion loss.

At a reached event time: first advance x/v/damage and the preceding interval's dwell by its actual local duration and update the rounded timestamps; then resolve terminal loss, then docking completion, then recompute the next force/eligibility branch. Simultaneous losses choose edge over damage as the displayed failure, while the receipt may list both causes. Loss beats delivery at the same instant. If no loss occurs, dwell reaching0.60 exactly at a closed containment/speed boundary succeeds even when the next open interval would be ineligible: the preceding valid duration has been earned. Band or speed branch changes themselves award nothing. A positive call may deliver multiple docks only through their own subsequent real eligible durations; there is no forced one-delivery-per-call restriction.

At terminal time, snap only the reached mathematical surface (edge boundary or damage100; v0 when its root is simultaneous), set phase won/lost and failure, recompute score, preserve the terminal receipt, and stop. Leave exact final x/v in place; do not zero terminal velocity. `lastStep.consumedDt` is the actual integrated local duration and `unusedDt=acceptedDt−consumedDt`; terminal time need not equal the host tick boundary. state.time is the rounded sum of call start time and consumedDt. Events and observation receipts include the final local interval and remain frozen on later calls. Retry creates a fresh state and call sequence; it is not a model input action.

## Numerical and framerate acceptance

Use IEEE-754 double precision and algebraic constant-acceleration pieces with robust linear/quadratic root selection. Surface snapping is allowed only after the corresponding mathematical event root has actually been selected and reached, and only within1e−9 in the corresponding physical unit; proximity alone cannot expand a gameplay region or grant free time. Exact event times/surfaces define the rules; no blanket ±epsilon success tolerance is part of the game. A tolerance of1e−10 s may deduplicate numerical representations of the same mathematical root only after that identity is established. Different true roots remain ordered even when closer than1e−10 s; never merge them into a tie, advance loss/delivery, supply missing dwell, or move an event across call-end. An exact tie means the physical predicates reach their thresholds at the same mathematical instant, and uses the order above. Do not leave an active boundary in a branch that repeatedly emits zero-duration pieces.

Each physical segment explicitly records its actual local duration, and each event records its call-relative offset. Absolute time/t0/t1 and offsets are rounded floating-point timestamps, not alternate integration inputs. A positive duration smaller than the timestamp's unit in the last place may therefore have t1===t0; still integrate that actual positive duration and resolve its event in order. Do not infer zero duration, freeze a normal small root, merge separate events, or invent epsilon time from equal rounded timestamps. For interval audit use the ordered durations, physical endpoints and consumedDt, not subtraction of large absolute timestamps. A truly zero-duration segment remains permitted only for an immediate outward edge terminal. This representation rule adds no time ceiling or new failure type; the ordinary precision guarantees below remain unchanged.

For ordinary supported audit timelines up to90 s, with equal time-indexed effective held commands/cancellation changes and inputs aligned to the same physical times, positive-dt partitions (including1/30,1/60,1/144 and irregular durations up to0.1) must agree within1e−6 m for x,1e−6 m/s for v,1e−5 damage,1e−7 s for model time/dwell and1e−6 s for event timestamps. Terminal phase, delivery count and reason must match unless the tested input was deliberately chosen within those tolerances of a competing exact threshold; those threshold cases require explicit analytical expectations instead of a loose equivalence claim. Additive force formulas and integral conservation should also be checked independently, not inferred solely from frame agreement.

Model tests may compare broader accepted positive dt with equivalent partitions, including a call that contains band entry and exit and a terminal remainder. An ordinary external model runner must archive the true complete state before/after, raw input/dt and lastStep for every actual call; only this complete ordinary model corpus claims interval-by-interval audit. Production state stores one lastStep/lastInput, at most3 permanent delivery receipts and one terminal receipt, with no call-history ring. Browser tests instead feed actual host input through RAF and observe real sparse snapshots plus those permanent receipts, and separately verify fixed-step scheduling at varied non-stalled RAF rates. Do not fill gaps by manufacturing hidden browser steps or claim sparse browser/video evidence is a full interval audit. A long RAF stall is deliberately clipped by the host; do not claim wall-clock equivalence for time it discards. No production hint solver, preset action route, model-control injection, or QA mutation endpoint is permitted.
