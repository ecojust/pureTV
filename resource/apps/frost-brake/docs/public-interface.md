# Frost Brake — public interface

Public interface for the paired public design and model contract. The exact field names below are accepted for implementation and independent observation, not permission to expose mutation, a solver or a route. JSON-readable numeric values must be finite; snapshots are deep copies through the existing `PureTVQA.snapshot()`. Prior drafts are preserved in the development evidence archive. The current interface has one latest-call trace and four small permanent outcome receipts; v3 makes local elapsed duration explicit even when absolute timestamps round equal.

## Model API and readable state

`PureModel.create(seed, difficulty)` and `PureModel.step(state, dt, input)` are the only production rule API. The host owns menu/pause/retry and supplies held controls and cancellation. step mutates its own state and returns it; consumers must not depend on a return value. It accesses no clocks, DOM, storage, network or rendering. No setters or alternate success path are exposed. Invalid seed/scenario/input and duration policies are exactly those of the model contract.

| State field | Exact meaning |
| --- | --- |
| `id`, `version`, `seed`, `scenario` | `frost-brake`, `0.1.0`, normalized recorded seed, scenario0..2 |
| `layout` | `{startX,lane:[0,100],halfLength:1.20,frostBands:[[l,r],...],docks:[{center,width},...]}` |
| `rules` | `{pushAcceleration:2.4,baseFriction:0.12,clawFriction:4.8,safeClawSpeed:5,loadCoefficient:12,damageLimit:100,dockSpeed:0.30,dockDwell:0.60,stickThreshold:0.35}` |
| `phase`, `failure` | playing/won/lost; null/edge/damage |
| `time`, `x`, `v`, `damage` | Rounded absolute model seconds, center meters, signed m/s, continuous load |
| `deliveries`, `dwell`, `score` | Completed count0..3, current eligible seconds, public score |
| `controlsReady`, `lastCancelEpoch` | Release gate and latest observed valid epoch or null |
| `lastInput` | null initially, then the exact latest input receipt defined below |
| `contact` | `{band,clawRequested,clawEngaged,eligible}` as defined below |
| `events`, `lastStep`, `nextSeq` | Current call events, latest exact-duration trace or null, next nonterminal call serial |
| `deliveryReceipts`, `terminalReceipt` | Up to3 preserved delivery event copies, and null or one preserved terminal receipt |
| `message` | Actual concise Chinese player feedback; presentation only, never authoritative physics |

Initial state has nextSeq=0, lastInput=lastStep=terminalReceipt=null, events=[], deliveryReceipts=[], and contact `{band:-1,clawRequested:false,clawEngaged:false,eligible:false}`. Other initial values follow the model contract. Layout/rules must be independent copies or deeply immutable; external mutation is not a supported production API. Score is `100*deliveries + (phase==='won' ? floor(max(0,100−damage)) : 0)`.

## Exact input receipt

lastInput has exactly these named facts: `rawInputKind`, `raw`, `xValid`, `rawAxis`, `requestedA`, `effectiveAxis`, `effectiveClaw`, `cancelled`, `epoch`, `epochChanged`, `gateBefore`, `gateAfter`, `reason`. rawAxis is the normalized −1/0/1 axis before gating; requestedA is raw a===true; effectiveAxis/effectiveClaw are the actual commands after gating. cancelled means raw cancelled===true. epoch is this sample's valid nonnegative safe integer or null; epochChanged means a valid epoch differs from an existing stored epoch, not first-baseline observation. reason is `cancel` for an epoch change or cancelled sample, otherwise `release` for the closed-to-open real-release sample, otherwise `blocked` while closed, otherwise `ready`. xValid requires an own finite numeric x. The release condition additionally requires raw x strictly between−0.35 and0.35 and own a===false. y/B/pressed edges do not participate.

rawInputKind records `object`, `array`, `null`, `undefined`, or the primitive's JavaScript type; only a non-null, non-array object supplies input fields. raw has fixed keys `x,y,a,b,aPressed,bPressed,cancelEpoch,cancelled`. Each is a descriptor `{kind,value}` of the original own property: absent=`missing`; other kinds are `undefined`, `null`, `boolean`, `finite-number`, `nan`, `positive-infinity`, `negative-infinity`, `string`, `array`, `object`, or the unsupported primitive's JavaScript type. value is the actual value for boolean/finite-number/string, otherwise null. Thus missing, nonfinite, malformed and explicit false/zero remain distinguishable without serializing unsupported object graphs. A rejected container supplies eight missing descriptors. A raw descriptor is observation data only, never a second input channel.

contact.band uses the model contract's forward-time band convention and is −1 off frost. contact.clawRequested is effectiveClaw, not a quarantined raw requestedA. contact.clawEngaged is effectiveClaw && band>=0. contact.eligible is the instantaneous closed containment/speed predicate for the current dock, false after all3 deliveries; it is not a promise that the next open interval stays eligible. Segment clawRequested has the same effective meaning. Derived contact may change on a no-time input sample, but physics/dwell cannot. These definitions distinguish a legitimately requested claw off frost from a stale raw hold that is still blocked.

## Latest call and interval trace

Each call made while phase is playing gets seq=nextSeq, then increments nextSeq once, including semantic no-time calls. lastStep is `{seq,startTime,requestedDt,dtKind,dtStatus,acceptedDt,consumedDt,unusedDt,input,before,after,segments,events}`. requestedDt is the original finite numeric value or null; dtKind uses the raw descriptor classification above (omitted dt is undefined). dtStatus is `duration`, `nonpositive`, `nonfinite`, `nonnumeric`, or `nonrepresentable`. acceptedDt is the requested positive duration only for `duration`, else0. input is a committed copy of lastInput. before/after are explicitly compact projections, each containing `{time,x,v,damage,deliveries,dwell,score,phase,failure,controlsReady,lastCancelEpoch,contact,message}`. They are not claimed to be complete recursive state snapshots.

unusedDt can be positive only when a terminal event truncates an accepted duration. A no-time call has acceptedDt=consumedDt=unusedDt=0, no physical segments and no physical events; it still reports semantic gate changes. All receipt values are committed copies: later steps must not mutate an earlier externally archived lastStep or a preserved delivery/terminal receipt. lastStep.events equals the current call's state.events by value; shared mutable references must not alter either after completion.

Each physical segment is `{t0,t1,duration,x0,v0,x1,v1,acceleration,axis,clawRequested,band,clawEngaged,damage0,damage1,eligible,dwell0,dwell1,deliveries,ends}`. duration is the actual local interval used for physical integration. t0/t1 are rounded absolute model timestamps, formed from call start plus local elapsed duration. Normally t1>t0, but a positive sub-ULP duration may round them equal; t1−t0 must never substitute for duration. axis is effectiveAxis; forces/contact/eligible describe the consumed open-time interval. dwell0 is the value at the start of that interval after any required invalid-interval reset; dwell1 is the value accrued on that interval before any same-time delivery reset. deliveries is the active dock index on the interval. ends is an array of actual reached reasons chosen from `band`, `zero`, `safe-speed`, `dock-speed`, `dock-edge`, `edge`, `damage`, `delivery`, `call-end`. duration>0 except an actual immediate edge terminal at time zero of a positive accepted call, recorded explicitly with duration0. No-time calls have no physical segment. The public equations and ordered actual durations allow independent recalculation of every segment's motion, frost exposure, load and dwell, even when rounded timestamps coincide.

Band boundaries are represented by ends containing band and by the adjacent segment/contact facts; there are no separate band-enter/exit events. At a band endpoint, reaching v=0, touching/reversing, resting, call-end and later departure follow the same forward-side law without inventing a movement event. A final contact observation may be inclusive/resting while the preceding open interval was outside; this is a zero-duration contact and contributes no load.

## Events and small permanent receipts

Events are fresh per nonterminal call and in actual chronological order; same-time events follow the model contract. Their common fields are `{type,time,offset,seq,index,x,v,damage}`. offset is consumed local call duration at the event (0 for a call-start semantic event); time is its rounded absolute timestamp. The offset may also round at floating precision, so ordered segments/durations and event indices determine actual order rather than assuming equal timestamps are an exact physical tie. seq identifies the containing call, and index is that event's zero-based position within its call. Only these types are emitted:

- `cancel` / `release`: only when controlsReady actually changes; extra `{gateBefore,gateAfter,epoch}`. Repeated cancelled/blocked input without a gate edge has no duplicate semantic event. epoch is the stored epoch after the sample. These events occur at call start and may occur on no-time calls.
- `delivery`: extra `{dockIndex,allowedCenter,speedLimit,dwell,deliveriesBefore,deliveriesAfter}`; allowedCenter is the two-number public center interval, speedLimit=0.30 and dwell=0.60. Copy the event once into deliveryReceipts.
- `won`: extra `{deliveries,score}`. `lost`: extra `{deliveries,score,failure,causes}`, where causes lists all actual simultaneous causes in edge-then-damage order and failure is the chosen reason. Copy the terminal event once into terminalReceipt and add `{phase,acceptedDt,consumedDt,unusedDt}` from the terminal call.

Damage is observed through actual segment integrals, never a per-frame loud collision. `delivery`/`won` use existing host sound names. No-time calls emit no physical transitions. Terminal call receipts include the actual final partial interval. All later step calls are complete no-ops, including nextSeq, events, lastInput, lastStep and preserved receipts. Retry/create resets the sequence and all receipts. There is no production audit ring, replay bank or external-storage dependency, and UI/physics must not read QA storage.

## Evidence scope

The future ordinary external model runner must archive the actual complete state before/after, original input/dt (with faithful type encoding when JSON cannot represent them), and lastStep for every actual call from creation through terminal. This contiguous ordinary model corpus, checked for every seq from0 without gaps, is the evidence that supports a full interval audit. Compute elapsed intervals from ordered segment.duration and consumedDt, not subtraction of rounded absolute timestamps. Terminal no-op checks also retain actual before/after states even though no new seq is produced. An independent auditor uses the public equations and this true corpus, never Model/pilot code or a private witness.

Browser gameplay and video retain actual sparse PureTVQA snapshots, actual control observations and the at-most3 delivery receipts plus one terminal receipt. They do not claim to expose every physical host substep. Never fabricate omitted browser calls, fill observation gaps by replaying the model, or present reconstructed intervals as observations. Sparse snapshots cannot independently prove every-interval physics; that claim belongs to the separate complete ordinary corpus. Host tick/elapsed are separately visible and can exceed exact terminal state.time because the host counts whole1/60 calls.

## Renderer and host integration

GameDef identity/title/seed/controls/hud/result/render/atlas follow the shared host. Use title `冰面刹停`, levelLabel `冰道`, levelNames from the design table, `holdConfirmAsA:true`, and actionLabels `['按住冰爪']`. game.json must also set `actions:1`, `actionA:'按住冰爪'` (with suitable English label); the builder-generated game-config.json controls the actual single phone action region. Do not hand-author generated config. B has no gameplay role. Instructions cover coast, frost-only claw, three simultaneous docking requirements, high-speed load and both losses. Render/hud introduce no rules.

Show signed direction/speed, safe claw speed5, effective request versus actual engagement, cargo integrity, active dock, dwell, elapsed time and differentiated failure. Formatting never feeds back into comparisons. At960×540 logical resolution, main viewport width688 spans20m at34.4px/m and camera center clamp(x,10,90); an always-visible overview shows full [0,100], all fixed bands/docks, both ends and the main crop. All3 scenarios use this same scale. The finite2.4m sled must correspond honestly to its local footprint; center claw/full dock/allowed-center rail are distinct. Main clipping changes no rule. Chinese labels live in DOM; atlas holds smooth original art and ASCII/meter primitives. The shared DOM supplies actual blur(14px) behind menu/pause/outcome dialogs. A current-motion arrow may show v but never a future path or recommended action.

Phone touch uses the shared broad single-action right region and free-origin left stick, with independent pause. Do not add small game-specific touch targets. Keyboard/remote ENTER hold, Space/Z A, direction, P/START pause, retry and menu retain shared cancellation. Pause performs no steps; active cancellation coasts. No shared-runtime changes are required.

## Separation and review boundary

Implementation owner reads accepted public rules and shared host; normal pilot/human-input owner uses public gameplay feedback without a supplied action route. Independent auditor reads public rules, actual observations/corpus, screenshots and criteria, never Model source, private pilot code, search diagnostics or a private witness. Root fully statically reads every newly created executable before first execution. The root accepted this ruleset for implementation; execution requires a separate full static review of every new executable.
