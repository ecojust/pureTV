# 冰面刹停 / Frost Brake

沿低摩擦冰道推动货橇，把整辆货橇依次停进三个越来越窄的交付区。松开方向仍会滑行；冰爪只有接触结霜带才会刹车。

这是 pureTV 百款游戏计划中的第 39 款，核心玩法为惯性与刹车时机。包名为 `com.ecojust.frostbraketv`，版本 `0.1.0`。三条冰道“晨霜直道”“回程冰湾”“窄岸货线”使用相同物理规则，各自有不同起点、结霜带和交付顺序。

## 操作与目标

- 左右方向键、遥控器方向或手机摇杆：向对应方向推货橇；松开后自然滑行。上下方向没有游戏动作。
- 按住 A（键盘 Space / Z，或游戏中的 ENTER）：降下冰爪；松开 A 收起。手机右侧整块宽触控区都是 A。
- 方向与冰爪同时生效。顺着滑行方向推动会减弱净刹车，反向推动会加强净刹车。在结霜带上停稳后，按住 A 能抵住推力。
- P / START / 独立暂停按钮：暂停或继续。B 在游戏中没有动作，在菜单中用于切换声音。结算后可确认重试，也可使用共享宿主的重试入口。

每次交付必须同时满足：**整辆货橇位于当前亮区内、速度不超过 0.30 米/秒、连续保持 0.60 秒**。越过中心点或高速穿过交付区都不能交付。完成一个交付区后，位置、速度和货损保留，下一目标立即亮起。依次完成全部三个目标获胜。

货橇越出冰道任一端，或货损达到 100，都会失败。没有超时失败。通常一局目标约为 30–90 秒；这只是设计范围，实际时长由操作决定。

## 看懂冰道

冰道总长 100 米，货橇长 2.40 米。全程概览始终显示固定结霜带、所有交付区、两端边界和主视图范围；主视图以固定比例显示附近 20 米。交付区边界与允许货橇中心停留的范围分别标示。

HUD 显示方向和速度、货物完整度、交付进度、停稳计时和已用时间。冰爪“已请求但未接触结霜”与“正在结霜带刹车”有不同反馈。安全冰爪速度为 **5 米/秒**：高于这个速度时，实际接触结霜的冰爪会持续增加货损。货损不恢复。

暂停会冻结模拟。输入取消或松手隔离期间，未暂停的货橇仍会自然滑行；先真实松开方向和 A，再开始新的操作。开始和继续菜单的确认键不会直接变成刹车命令。

## 公开规则与实现

- [公开设计](docs/public-design.md)：三条冰道、操作、物理量、呈现要求。
- [模型规则](docs/model-contract.md)：分段匀加速积分、结霜接触、持续货损、连续停稳、终局与数值约定。
- [观察接口](docs/public-interface.md)：原始输入分类、有效命令、逐段实际时长、交付与终局回执。

完整推力为 2.40 米/秒²，普通冰面阻力为 0.12 米/秒²；实际接触结霜时，冰爪额外提供 4.80 米/秒²。静止时使用静摩擦，不会因阻力翻转速度。冰爪货损率为 `12 × max(|速度| − 5, 0)`，只在实际接触结霜时累计。

模型入口为 `src/main/assets/game-model.js` 的 `PureModel.create(seed, difficulty)` 和 `PureModel.step(state, dt, input)`。浏览器使用 `PureModel`；CommonJS 直接导出同一个 `{ create, step }` API。模型不访问墙钟、DOM、网络或存储，不提供修改分数、强制成功或推荐路线接口。终局后所有调用完整保持最终状态。

共享宿主以固定 `1/60` 秒调用模型。模型自身接受实际持续时长，并在边界和事件处进行代数分段；录入的 `segment.duration` 是物理计算依据，绝对时间戳可能因浮点精度而舍入。生产状态仅保留最新调用、最多三份交付回执和一份终局回执。

## 构建与验证范围

在仓库根目录使用共享构建工具：

```sh
python3 resource/game-kit/build.py \
  --game resource/apps/frost-brake \
  --output /workspace/scratch/hundred-games/frost-brake/build
```

`game-config.json` 与 `assets-index.json` 由构建工具生成，不手写。`game.json` 中的 `actions: 1` 让手机 A 使用整个右侧触控区。

首轮模型验证的 36 项规则测试全部通过，包括非结霜区冰爪无额外作用、整橇位置与速度及连续停稳共同交付、相同输入时间线的帧划分一致性。三条冰道各完成一次普通反馈操作获胜和一次自然失败，共 6 局、7,771 次完整实际调用；独立公开规则审计检查了这些调用中的 7,869 个物理片段，共通过 3,253,715 项检查。独立审计只读取公开规则与真实观察，不导入或重放生产模型。

浏览器控制首轮通过 7 项检查，覆盖菜单、实际手柄页与 WebSocket 传输、惯性与霜带刹车、输入取消、断连暂停、暂停继续和重试。画面证据分别记录 960×540 与 1280×720 完整用户视口，并保留普通交付、边缘失败和高速冰爪货损失败的真实观察。截图中的画布尺寸、物理图形映射、弹窗模糊与完整文字需要结合各自原图和审阅范围判断。

本版本的签名 APK 使用 `frost-brake-0.1.0.apk`，正常运行录像使用 `docs/gameplay-0.1.0.mp4`；验证范围与产物哈希记录在 `docs/verification.json`，签名记录在 `docs/signing-receipt.json`，画面审阅记录在 `docs/art-review.json`，录像说明在 `docs/gameplay-0.1.0.json`。实际签名、大小、源码身份、图像审阅和录制结论以对应报告为准。开发证据保留首次失败与实际观测，不以计划或旧游戏结果代替验证。

上述普通六局保留了每一次实际调用的完整前后状态、原始输入和回执；它们没有无时长调用或终局后空操作，不把这些规则夹具的覆盖算作普通流程。浏览器截图、录像与稀疏快照不能冒充完整逐段记录，也不能用重放补造遗漏步骤。浏览器软件渲染结果不代表实体电视或实体手机性能；本候选没有硬件验证结论。
