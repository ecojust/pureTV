# 灯塔节拍 / Lantern Rhythm

观察灯号的方向、长短和顺序，再按节拍传回信号，依次点亮沿岸三座灯塔。示范只展示当前灯号；复现阶段给出拍点和计时，不显示待答的方向或长短。

## 操作

手机与电视接入同一局域网，扫描电视画面的二维码。左侧摇杆选择方向，右侧上半区按住 A 传递灯光，松手结束该灯号；右侧下半区 B 可重听当前一段。按下 A 时锁定方向，按住期间改变摇杆不会改变这一拍。

键盘方向键或 WASD 选择方向，按住空格或 Enter 发出灯号，B 重听，P 暂停，R 重试。电视遥控器方向键选方向，按住确认键传递灯光，菜单键重听。手机 START 开始或暂停；开始与结算菜单可用左右方向选择关卡，B 切换声音。

每拍相隔 1.5 秒，短灯约按住 0.30 秒，长灯约按住 0.72 秒。先在示范阶段记住整段，再跟随倒数选择正确方向、按下并松开 A。短灯接受 0.14–0.46 秒，长灯接受 0.56–0.88 秒；起拍允许前后 0.22 秒偏差。过早、过晚、方向错误或长短不符会算一次失误，未完成的本段会重新示范，已经点亮的灯塔保留。

三关每段分别有 3、4、5 个灯号，每关均需完成三段。整局有两次主动重听机会，重听会清除本段尚未完成的进度并消耗时间；B 不用于暂停。四次失误或 90 秒有效游戏时间耗尽会结束本局。

暂停、失焦或断线会取消尚未松开的灯号，不给分也不算失误。继续时先松开按键，未答拍点会重新倒数，已正确传出的前缀保留；取消不会展示答案或返还重听次数。

## 源码与验证

规则按 60 Hz 固定步长判断实际按下、持续时间和松开。短灯与长灯的有效区间互不重叠，单帧按钮脉冲不能代替真实按住。输入取消协议与局域网手机手柄组件见 [game-kit](../../game-kit/README.md)。

```bash
node --test resource/apps/lantern-rhythm/tests/game-model.test.cjs
node resource/apps/lantern-rhythm/tests/independent-temporal-review.mjs
node resource/apps/lantern-rhythm/tests/independent-pilot-review.mjs --output /tmp/lantern-pilot-review
```

[独立时序报告](docs/independent-temporal-review.json)按整数帧边界核对起拍、短长时长、重听成本与取消处理，并用只记住实际示范灯号的观察器完成三关模型解法。受控输入和模型解法不作为浏览器录像或设备实测证据。

[观察脚本独立报告](docs/independent-pilot-review.json)让相同的可见灯号历史搭配不同隐藏答案，核对普通按键决策一致，并用禁止读取私有字段的受控快照检查记忆、重听和取消。这些合成观察用例不代表一次实际通关。

模型、输入协议、浏览器界面与实际录像分别验证。最终记录随发布产物提供；浏览器验证不代表实体电视或手机实测。
