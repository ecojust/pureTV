# Magic Jewelry TV：玩法依据与实现范围

本应用对应红白机《Magic Jewelry》（钻石方块），不是四格骨牌游戏。这里的 JavaScript 游戏状态机、画面和音频均为独立实现；不运行 NES ROM，不包含 CPU 模拟器，也没有把原作汇编程序、CHR 图像或原曲录音放入 APK。

## 规则依据

公开的 [Magic Jewelry 资料与反汇编说明](https://github.com/freem/magic_jewelry/tree/b152dabfaf748788299b6e8d3c4320793e14da29) 及其 [RAM 字段注释](https://github.com/freem/magic_jewelry/blob/b152dabfaf748788299b6e8d3c4320793e14da29/ram.inc) 用于核对棋盘尺寸、按键和数值事实。只参考事实与行为，没有复制其程序实现。原作由 Hwang Shinwei 制作；原作设计及名称不归本项目所有。

| 原作特征 | 本版本实现 |
| --- | --- |
| 棋盘 | 6 列、13 个可见行，另有顶部 2 个隐藏行 |
| 下落单位 | 三颗宝石组成竖列，在第 4 列出生；NEXT 显示下一列 |
| 普通宝石 | 6 种；随机值的两种回退使红色和蓝色出现机会较多 |
| 换序 | A 或 B 都将底部宝石移到顶部；按住 SELECT 再按 A/B 交换顶、底两颗 |
| 消除 | 横向、纵向、两个斜向连续 3 颗及以上同色；交叉匹配去重、同时闪烁消除 |
| 重力与连锁 | 消除后各列以每格 4 帧向下填空，保持原顺序；全部落稳后再检查新形成的匹配。坠落过程可以暂停，不接受换序或横移 |
| 等级与魔法列 | 每次落列完成全部消除/连锁后，最多扣除 70 颗并兑现一级魔法列；多余进度保留至下一次结算，连续奖励不消耗 NEXT。魔法列清除接触颜色及自身，完成重力/连锁后才推进速度与场景配色；落到空底只移除自身 |
| 下落速度 | 初始每 63 帧下移一格；采用公开资料中前 32 档帧数，之后 11 帧，48 档起 8 帧；普通左右重复间隔 8 帧 |
| 软降 | 按住下方向每 2 帧一格；新一列出现后须先松开再按下才继续软降，避免意外连锁落地 |
| 顶出 | 未获得魔法奖励时，结算后隐藏行仍有宝石则结束；获得奖励时先生成魔法列，出生列未堵塞即可尝试抢救其他列的隐藏宝石。任何新列出生位置被占据仍会结束 |

### 计分

每波消除的基础分为 `100 + 10 × 连续有消除的落列次数`，该次数最高为 9；落列未产生消除时减 2，最低 0。第二波连锁基础分翻倍，之后逐波再翻倍。

消除 `n` 颗时，分值单位为：

```text
n + max(0, (n - 3) × (n - 2) / 2)
```

因此第一波基础为 100 时，3 颗为 300 分、4 颗为 500 分、5 颗为 800 分。另按锁定列高度增加 0–9 分。这些计分事实依据公开字段和行为注释重新表达为独立算法；不保证与所有盗版变体、PAL 时序或特定 ROM 的每一帧完全一致。

## 操作

- 标题画面：SELECT 切换 1 PLAYER／2 PLAYERS，START 开始，初始画面等级为 000。
- 游戏：左侧浮动摇杆左右移动、向下软降；右侧三分之一整区换序（键盘 A/B 同功能）；SELECT+动作区交换上下宝石。操作区禁止文字选择及长按菜单。
- START 暂停／继续；暂停后 SELECT 切换音乐。电视侧栏也有音乐开关。
- 结束后 START 返回标题，再按 START 开始新局。
- 手机没有按下摇杆时圆盘隐藏；按下位置就是本次中心。松手、触控取消、切后台、断线都会清空输入。

## 局域网双人扩展

原作经典单人模式之外，提供双棋盘对局。两位玩家从同一个种子获得相同的普通宝石序列，各自的棋盘、NEXT、等级、分数和魔法奖励独立。不向对方棋盘投放垃圾，不把一人的随机读取推进另一人的队列。

任何仍在游戏的参与玩家断线时，两块棋盘一起暂停；全部恢复连接后自动继续。手动暂停不会被网络重连取消。已顶出的玩家不再阻挡对局；两位都结束后显示 GAME OVER。该模式是本应用新增的局域网玩法，不宣称原作已经提供。

## 本轮规则校正与可核对依据

参考版本固定为上述资料仓库的 `b152dabf`，本轮只核对以下事实并独立表达为状态机：

- [落列结算与奖励判定](https://github.com/freem/magic_jewelry/blob/b152dabfaf748788299b6e8d3c4320793e14da29/original.asm#L1462-L1493)：`lbl_e74e` 每次只判断并扣除一次 70 颗，再返回魔法列生成位置；不是把累计进度一次性换成多级。因此大连锁后的多份奖励现在逐列出现，速度不会一次跨过多档。
- [隐藏行结束判定](https://github.com/freem/magic_jewelry/blob/b152dabfaf748788299b6e8d3c4320793e14da29/original.asm#L1548-L1563)：`lbl_e7b6` 位于魔法奖励分支之后。此前实现先检查隐藏行，可能剥夺已挣得的魔法列；现在奖励优先，允许通过清除另一处可接触的同色宝石来解救隐藏行。
- [阶段更新](https://github.com/freem/magic_jewelry/blob/b152dabfaf748788299b6e8d3c4320793e14da29/original.asm#L2467-L2510)：魔法列完整结算后设置的 `next_level_flag` 推进速度、音乐/配色阶段；配色索引循环八档。本实现让速度和新绘的八组场景配色在全部坠落/连锁落稳后一起改变。双人各棋盘按各自阶段着色，共用背景不跟随其中一人变化。

这里没有移植或捆绑参考汇编程序、图块、调色板数值或音乐；八阶段颜色为独立配色。当前只实现阶段视觉与速度推进，仍播放本项目原创配乐，不宣称复刻原版逐关曲目或硬件调色。

## 画面和声音

棋盘、宝石倒角、文字点阵、云带、城市和举火炬雕像由代码自绘。内部画布为 256×240，电视显示时等比缩放。

0.5.2 对照[初代 Magic Jewelry 的单人游戏画面](https://raw.githubusercontent.com/libretro-thumbnails/Nintendo_-_Nintendo_Entertainment_System/master/Named_Snaps/Magic%20Jewelry%20%28Asia%29%20%28En%29%20%28Unl%29.png)重排画面：中央偏左的棋盘使用 16 像素格与明亮边框，NEXT 放在左侧，SCORE／JEWELRY／LEVEL 集中在右上，右侧从火炬、冠冕到衣袍的雕像完整露出。移除遮住雕像的大块统计面板和通用月亮星空，恢复暗底彩色云带、左下城市与高对比雕像的构图。画面、电视侧栏与手机的 LEVEL 均从 000 起，与原版屏幕标记一致；状态序列化同步使用模型原有的零起始等级，升级规则和速度没有改变。

双人画面为本应用扩展：两侧棋盘与各自 NEXT、分数独立，雕像缩小放在中央空隙，不作为原作单人画面的复刻。主预览取单人开局的真实手机输入，双人截图另存。背景、衣褶、文字和宝石全部由代码重绘；不打包参考截图或提取原作 CHR，也不宣称所有点阵与硬件颜色逐像素一致。

配乐为本项目新写的短 8-bit 合成旋律，音效也由 Web Audio 合成。没有捆绑《龙的传人》或其他原曲、录音、提取音轨。静音状态和最高分保存在电视应用本机；退出会停止声音、轮询和局域网服务。

## 验证与边界

单元测试覆盖匹配去重、两个斜向、重力顺序、连锁、魔法列、跨多个等级阈值的逐列兑现、魔法奖励抢救隐藏行、出生堵塞、双人独立阶段配色与速度、等级阈值、换序边沿、软降重新按下、碰撞、隐藏行顶出、双人公平队列、暂停和断线恢复。浏览器测试另验证扫码手柄输入、双语显示、绘制、音频和退出清理。

本版本采用可重放的独立伪随机数生成器，而非原作的逐帧随机状态；闪烁时长、每格 4 帧坠落速度和自绘动画也不是逐帧移植。尚未做真实电视与原机的逐帧并排测量，浏览器结果不能代替真实手机的局域网时延与电视手感测试。
