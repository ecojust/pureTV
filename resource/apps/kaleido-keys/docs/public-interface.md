# Kaleido Keys — public interface and evidence

Public specification; implementation and execution evidence are recorded separately. The [public design](public-design.md) and [model contract](model-contract.md) specify all authored data and transitions. These documents make no executed-play, implementation, performance or release claim.

## Shared host and controls

Use the unchanged shared runtime's create(seed,level), step(state,1/60,input), GameDef render/HUD/menu/pause/results and PureTVQA.snapshot. GameDef id is `kaleido-keys`, seed745, holdConfirmAsAtrue. game.json actions2 selects the phone's continuous right-third upper-A/lower-B split, with the midpoint in lower B. Action labels are `放置 / 旋转 / 确认` and `取回 / 反向 / 清空`; actual contextual focus actions remain visible on television. Task labels come from the public configuration.

Directions navigate the bounded3×3 focus board; A/B behavior depends only on the current focus and source occupancy, exactly as the design table states. CHECK/A is the sole submit action, CHECK/B the sole whole-source clear. Pause/continue and retry are independent host actions and cannot be repurposed as editing commands. Enter uses held A so menu confirmation cannot silently place a piece or submit after entering play.

On start/resume, blur/hidden, input cancellation, disconnect/reconnect and source-session replacement, the shared host quarantines stale held A/B/confirm. Actual local keyup or a received raw remote false releases quarantine; absence and synthesized cancelled-neutral samples do not. The model also requires a later noncancelled full-neutral sample. A/B/direction holds do not repeat. Verify B>A>direction consumption, including A+B at CHECK and a held Enter across menu/pause. Cancellation consumes admitted informational elapsed time unless the host pauses. No model timeout or time-based loss exists.

`PureTVQA.snapshot()` supplies a deep JSON copy of the actual wrapper `{id,phase,paused,tick,elapsed,level,best,model,renderer,frameTimesMs,connection}`. Model contains the complete public canonical source, focus, palette, visible target window, current geometry/inspection/matches, stocks, counters, gate and bounded receipts. `PureGame.key(name,down)` is ordinary held keyboard input. Neither observation nor controls provide state mutation, arbitrary target loading, alternate origins or a solver. Renderer must not consult QA/pilot storage. A browser observation does not expose the unobserved model calls between reads.

## Rendering contract

The only model API is create/step/config. Render read-only from actual state plus the immutable configuration. `state.source` is the six physical editable pieces; `state.stock` the remaining physical counts; `state.target` the public `{order,sector,window}` actually shown on the target inspection card. Whole target geometry is the configured task.target.cells/instances, generated by the public inverse-window rule. Whole current geometry is state.pattern.cells/instances. No desired-source answer array exists.

For complete circular keys, map every instance x/y through one isotropic scale and origin. Its glyph tile is ordinary or left/right-mirrored according to mirrored, rotated by instance.angle and sized to the public polygon scale. Both center and glyph shape must follow the same sector reflection. Polygons use the exact local vertices; mirrored tiles reflect local x, not y. Each tile can include restrained baked enamel lighting, but an apparent directional notch/tooth must not move sides. Public emitted x/y/angle have12-decimal rounding defined in the model contract. They are display outputs, never judging tolerances.

Inspection strips remove the sector's global rotation. Display each six-cell window in the same inner-to-outer, left-to-right order as its array. Use the normal or mirrored glyph tile and `turn*π/2`; show the integer turn beside it. A heading such as `SECTOR 1 · MIRROR` identifies the fixed target sector, using zero-based sector indices everywhere. The live strip uses the same target.sector at the current order. Thus wrong-order play can have six matching window cells while whole-key structural order remains wrong. Show that distinction clearly: `ORDER 4 / 3` is not accepted even when `WINDOW 6 / 6`.

The editable area is the explicit `SOURCE GRID` / 源扇区展开: a logical3×3 table with the six source cells in columns0/1, inner/middle/outer rows from top to bottom, and tools in column2. This unrolled chart deliberately follows focus navigation; it is not a physical rotation or reflection of the source wedge. Draw source glyphs at their ordinary source-frame turn without mirroring. The full live circle separately highlights its actual upward sector0 and true geometric socket positions. LIVE/TARGET inspection windows are likewise row-major unrolled charts, preserving their actual local turn and mirror parity rather than undoing reflection. Both whole circles and both inspection windows remain available during play; every source glyph, target glyph and target empty socket can be identified. Inspection differences are current feedback, never permanently earned checks. Full plate matches remain provisional until CHECK/A.

Show remaining rejections, current/target order, selected glyph with its stock, all inventory counts, source focus, and contextual A/B. Empty placement with depleted stock has an explicit blocked-stock message and spends no rejection. Clear announces how many physical pieces returned while preserving failures. Feedback may explain `MIRROR: swap lanes; reverse turns`; it must not perform the edit or supply a precomputed route.

Use smooth original enamel, brass and glass art in one local atlas. Bake three ordinary and three reflected glyph tiles once; run-time drawing uses shared rect/line/circle/sprite/text batching, not a new shader or a per-frame Canvas atlas. Essential ASCII canvas labels are at least24 logical pixels; Chinese instructions/results are DOM. Preserve the shared actual blurred modal background. Review the complete original960×540 and1280×720 screenshots for source/target readability and all HUD/sidebar content. Keep normal frames below8192 quads, then measure actual WebGL calls and frame costs; Canvas fallback is reported separately.

## Ordinary current-observation pilot

The normal pilot may read only fields that are visibly meaningful now: target.order/sector/window, source glyphs/turns, focus, selectedGlyph, stock, current live inspection/matches, phase and remaining rejections. It must make one actual held-edge action, release, observe the resulting board and decide again. Input gates/counters may be logged for evidence; they are not a solution source. The pilot must not import model production code/helpers, simulate future states, enumerate candidate arrangements, read cached target source answers, use a saved route, jump state or ask a privileged fixture to win.

A legitimate policy reads a displayed mismatching target inspection cell, applies the displayed mirror rule if that sector is odd (exchange lanes, reverse turn), and identifies the corresponding actual source socket. It navigates using the currently observed focus, retrieves a wrong glyph with B, chooses the visible palette, places only when stock permits, and rotates the observed piece one quarter turn at a time toward the current visible requirement. It observes after every action. Empty target cells require corresponding empty source cells. It changes order through the visible ORDER control, and submits through the visible CHECK control only after the complete current pattern matches. This is direct interpretation of a visible reference and published spatial law, not a hidden target vector or canned route. If expected live feedback does not follow the rule, preserve the failure and stop instead of adding a force-success fallback.

Natural rejection loss navigates an unchanged fresh empty source to CHECK and makes four real A press/release submissions. Each target has occupied orbits so every unchanged submission fails. Source edits, glyph selection, order changes and clear can be exercised naturally before a later success; retries and first failed attempts remain in evidence. A normal success recording should show the initial task, physical source placements, real mirrored changes, understandable target comparison, an accepted CHECK/A and the genuine result. Aim for30–90seconds of actual play, without padding by slides or silently substituting synthetic state.
