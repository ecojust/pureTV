# Island Dominoes model contract

UMD `PureModel` exports `create(seed=1,difficulty=0)`, `step(state,dt,input)` and `TICK_HZ=60`. Three fixed, fully public puzzles contain 6/6/7 islands and 5/5/6 bridge pieces. Every physical piece has a unique ID even when its printed length and color match another piece. Retry restores the same authored puzzle. Production contains no solver, reference placement, hidden route or forced outcome.

## Exact geometry and local placement rules

Island positions `gx,gy` are integer grid coordinates. A bridge piece joins two distinct islands in a straight segment; its numeric source end may start at any color, while its colored target end must land on an island whose `color` equals `piece.targetColor`. Direction matters: reversing endpoints is allowed only if the newly chosen target has the required color. Length is Euclidean in grid units, tested exactly as `(target.gx-source.gx)^2+(target.gy-source.gy)^2===piece.length^2`. A 3-by-4 diagonal is length 5, not Manhattan length 7. All arithmetic for these tests uses bounded integers.

A local placement is rejected in this order: same source/target island; wrong squared length; wrong target color; a third island lying on the segment interior; a previously occupied unordered island pair; any forbidden intersection with an existing bridge. Proper crossings, collinear overlaps, and endpoint/interior touches are forbidden. Exactly one common island endpoint is allowed only when the two segments meet at that single point: sharing an island never permits an overlapping collinear portion. Segment tests include their endpoints, using exact integer orientation and bounding comparisons. No floating epsilon is used.

The preview is computed entirely from this public geometry. Previewing or picking a bridge never reserves a piece, changes any island degree or alters the network. `preview.valid` means locally legal, not necessarily a final connected network; its separate resulting-component fields expose the consequence of placing the last piece.

## Public geometry and schema

Canvas is 960×540. `board={x:90,y:110,unit:58}` maps a grid point to `x=board.x+gx*board.unit`, `y=board.y+gy*board.unit`; authored coordinates fit gx=0…8 and gy=0…5. `islandRadius=18` is the map marker radius, not an alternative collision rule. Bridges connect the exact island centers. Right-side bank card centers are `x=748+(index%2)*112`, `y=150+floor(index/2)*108`. These positions are UI coordinates and do not affect bridge length.

- `colors[]`: `{id,label,glyph,rgb}` for coral, teal and gold, with redundant C/T/G labels for color accessibility. rgb is an array of three 8-bit channel integers.
- `islands[]`: `{id,gx,gy,x,y,color,degree,incidentPieceIds,componentId}`. IDs are `I1` etc. Components are undirected; every isolated island is still a component.
- `pieces[]`: immutable identity/attributes plus current availability: `{id,length,targetColor,x,y,placed,bridgeId}`. IDs `P1` etc remain stable. Used pieces stay in this array and remain visible in the bank.
- `bridges[]`: placement-order records `{id,pieceId,sourceId,targetId,length,targetColor}`. `id` is `bridge-` plus the unique piece ID. The array is the actual network, not a preview. Removing the last record restores that exact piece instance.
- `availablePieceIds[]`, `placedCount`, `remainingPieces`, `componentCount`, `connected` and `largestComponentSize` are derived current values. `islands[].incidentPieceIds` is the occupancy ledger and is rebuilt from actual bridges after commit/undo.
- `stage` is `bank`, `source` or `target`; it is separate from terminal `phase`. `selectedPieceId` identifies the currently selected available piece (null after all pieces are committed), `heldPieceId` is null in bank and the selected piece ID in source/target. `selectedIslandId` identifies the spatial cursor. `sourceId` is null except in target stage. `cursor={kind,id,x,y}` is the selected bank card or island, or null when terminal all-pieces-used leaves no available bank card.
- `preview` is null outside target stage. In target it is `{pieceId,sourceId,targetId,length,targetColor,distanceSquared,requiredSquared,targetColorMatches,valid,reason,blockingPieceId,blockingIslandId,resultingComponentCount,wouldFinish,wouldConnectAll,wouldLoseDisconnected}`. Reason is null when locally valid, otherwise `same-island`, `length`, `color`, `through-island`, `occupied` or `intersection`. Blocking IDs refer only to public objects. `resultingComponentCount` is null for a locally invalid placement. `wouldFinish` means one piece remains; `wouldLoseDisconnected` is true only for a locally legal final placement that leaves multiple components.
- Lifetime counters `totalPlacements`, `undos`, `cancels`, `failedCommits`, `placementAttempts` never decrease. `maxFailedCommits=3`. `totalPlacements===placedCount+undos` on all ordinary states. Selecting/picking/canceling is not a placement attempt.
- `lastPlacement` is null or `{pieceId,sourceId,targetId,accepted,reason,at,tick}`. Reason is null when accepted, or the local preview reason when rejected. It describes the latest actual target-stage A attempt; it is not mutated by undo. `lastUndo` is null or a copied bridge record with `at,tick`. `lastAction` and `events[]` contain public actions/results; events reset each outer step and are capped at 32.
- `width,height,seed,level` (1…3), `difficulty` (0…2), `levelName`, `phase` (`playing`,`won`,`lost`), `tick`, `elapsed=tick/60`, `timeLimit=90`, `remaining`, `score`, `message`, and `lostReason` (null, `invalid`, `disconnected`, or `timeout`).

## Selection and A/B controls

Initially the network is empty, stage is bank, the first available piece is selected, and the island cursor starts at the first island in array order.

In bank, directions select among available pieces using their displayed card centers x/y: require a strictly forward candidate along the input axis, then choose minimum squared Euclidean distance, minimum absolute perpendicular displacement, and pieces-array index. Used pieces are excluded. With no eligible candidate selection stays unchanged; there is no wrap. Thus down from the first card chooses the card below it, not the card to its right. Every nonempty subset of the authored bank is checked for selection reachability. A picks the selected piece without changing inventory and enters source stage, selecting the first island. In source, A chooses the currently selected island as source and enters target stage; the target cursor initially remains at that same island, so a destination must be chosen before a valid placement. In target, A attempts the visible preview. A valid placement commits one actual bridge, updates all occupancy/components, and returns to bank. Select the first remaining piece after the committed piece's array position, or the first remaining piece if there is none after it. On an illegal attempt remain in target with the same selections, increment failedCommits exactly once and show the public reason.

In source/target, directions use the selected island's integer position. Eligible islands have strictly positive projection on the input axis: right means larger gx, left smaller gx, down larger gy, up smaller gy. Among eligible islands choose minimum squared Euclidean distance, then minimum absolute perpendicular displacement, then original islands-array index. No eligible island leaves selection unchanged. Navigation uses geometry only, not legal-bridge filtering; all authored selection graphs are checked for reachability.

B in target returns to source stage, clears sourceId, and restores the cursor to the former source island. B in source returns to bank and reselects the held piece; no network or inventory changes. Each of those phase cancellations increments cancels. B in bank removes the most recently committed bridge, returns exactly that piece to availability, selects its bank card, and increments undos. With no placed bridge it is a harmless no-op. B does not refund time, failedCommits, placementAttempts or totalPlacements. Terminal states cannot be undone; use the shared R/retry action for a fresh round.

## Completion, failure and clock

After each locally valid commit, all pieces used triggers immediate undirected connectivity inspection. If every island belongs to the same component, win. Otherwise lose with disconnected: a cycle among some islands does not connect an isolated island. The final commit is never accepted solely because its edge count equals islands−1. Three illegal target-stage A attempts lose with invalid, even if each repeats the same visible invalid preview. Held A does not repeat. Local illegality does not consume/remove the piece or change bridges, occupancy or selection.

Each fixed tick first advances the active clock and loses at elapsed≥90 before any action, including a would-be winning last commit. Pending B then has priority and discards simultaneous A and navigation for that tick. Otherwise navigation precedes A on the resulting selection. Priority is per fixed tick: a held direction may move on later substeps of the same larger-dt call after B. Direction uses the larger absolute axis, horizontal on ties, .25 deadzone, immediate new-direction movement, first held repeat after 20 ticks and subsequent repeats every 10. A/B are press-edge actions. Zero/subtick dt may cache button edges but performs no action before a full tick; coalesced A edges produce only one action.

dt is finite-clamped to [0,.25] with a fixed 60 Hz accumulator. Cancellation-owned input or a changed cancelEpoch clears pending buttons/repeat and is neutral for that sample while the clock advances; it preserves selections, held preview and actual network. First epoch initializes without canceling normal input. Shared pause freezes by not calling step. Terminal step calls freeze every field, including timers, events, preview and input bookkeeping.

Current score is `placedCount*100+(islands.length-componentCount)*40`; a win adds `1000+floor(remaining)*5`. Undo removes current placement/connectivity progress but never adds repeatable points. Rendering reads actual public geometry, totals and preview only. Formal boundary fixtures and independent integer geometry/solver proofs are separate from ordinary full-input play evidence.
