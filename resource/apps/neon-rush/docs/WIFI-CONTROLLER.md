# pureTV Wi-Fi 手柄接入（0.1.1）

本版本遵循 [puretv-joystick 接入与测试说明](../../../../puretv-joystick/README.md)，对应 SDK 提交 `a5fd8b2a`。ESP32 实体手柄使用原生 TCP 输入服务；扫码手机继续使用原有 HTTP/WebSocket 房间。两者共用游戏输入取消与暂停逻辑。

## 连接与操作

1. 在电视上打开霓虹飞车，让电视与 pureTV Wi-Fi 手柄连接同一个局域网。
2. 菜单右侧显示“可被 Wi-Fi 手柄搜索”后，按实体手柄的搜索键。搜索键由手柄固件处理，游戏不把它当按键消息。
3. 当前固件只在发现一个服务时自动连接。同网有多个接收服务时，只保留目标电视游戏的接收服务。
4. 连接后按 START 开始比赛；再次按 START 暂停或继续。

| 实体键 | 霓虹飞车动作 |
| --- | --- |
| LEFT / RIGHT | 左右转向 |
| DOWN | 刹车 |
| UP | 油门方向；本作默认自动加油，无需一直按住 |
| A / X | 按住漂移，配合转向；正常松开可触发小喷 |
| B / Y | 氮气满时加速 |
| START | 开始、暂停、继续 |

X/Y 是实体手柄的 A/B 别名，键盘仍沿用已有按键表。Wi-Fi 实体手柄连接时优先取得控制席；扫码手机不与它合并按键。控制源切换或手柄断开会清除旧输入并暂停比赛，重新按 START 才继续。

## 发现服务

共享 Android 宿主先启动 TCP 监听，再使用 `NsdManager.PROTOCOL_DNS_SD` 注册：

- `serviceType`: `_puretv._tcp`
- `serviceName`: 游戏的本地化名称，例如“霓虹飞车”；发生重名时显示系统实际分配的名称。
- `port`: 实际监听端口，首选 `8765`；端口被占用时使用系统分配的端口并如实广播。
- TXT: `version=1`

注册失败会显示不可发现状态，原有遥控和扫码入口仍可用。游戏退到后台、关闭、WebView 进程退出或网络房间重建时，关闭 TCP 并撤销注册；停止后迟到的注册成功也会撤销。

## TCP JSONL v1

每条消息为 UTF-8 JSON，以换行结束；兼容 CRLF、TCP 分段与同一包中的多条消息。使用规范中的 `controller_id`、递增 `seq` 和九种 `key`：

```json
{"type":"button","seq":12,"controller_id":"esp32-001122334455","key":"A","pressed":true,"action":"down","duration_ms":0}
```

服务端逐条回复同序号 ACK，例如：

```json
{"type":"ack","seq":12}
```

- `down` 为按下；`long_press` 延续同一按住状态，不再次产生按下边沿。
- `tap` / `long_release` 为释放。快速按下再释放也会保留一次真实按下脉冲。
- `sync` 更新按键状态，动作键和 START 的同步按住必须先释放，不能直接触发氮气、开始或暂停。
- 同一连接重复或旧序号只回复 ACK，不重复执行。重连重新接受从 0 开始的序号，分配新的连接代际；同 ID 的新连接可替换旧半开连接，不同 ID 不抢占现有控制席。
- A 与 X、B 与 Y 分别按物理键合并，释放其中一个不会释放仍按住的另一个。
- 连接时发送 `hello` 和九条 `sync`，之后约每 5 秒发送 `ping`；三种消息均回复同序号 ACK。长按期间保持心跳，不套用扫码手柄的 750ms 输入过期规则。
- 检测到 EOF/网络错误立即释放输入；连续 20 秒没有有效消息时断开并清除按键，避免静默失联卡键。重复 `hello` 不清除当前按住状态，`ping` 仅保活。

## 使用仓库虚拟手柄

在电视运行此版本，电脑与电视处于同一局域网，执行：

```sh
python3 puretv-joystick/bridge.py 电视IP --port 8765
```

浏览器打开 `http://127.0.0.1:8767/`，点击“连接游戏”。如果游戏广播的实际端口不是 8765，请使用该端口。鼠标、触控或键盘可操作九个按键；约 500ms 触发长按。此网页使用原 SDK 直连指定地址，实体手柄的 mDNS 搜索需另行验证。

## 验证边界

软件回归包含实际环回 TCP 消息/ACK、Android 宿主与 NSD 注册生命周期、真实游戏浏览器输入链路。Robolectric 的 NSD shadow 验证的是注册字段和调用顺序；浏览器联调使用测试桥，均不能代替实体电视与 ESP32 在同一 Wi-Fi 下的发现和操作测试。完整结果在 [0.1.1 验证记录](releases/0.1.1/verification.json) 中记录，实体测试状态明确列出。
