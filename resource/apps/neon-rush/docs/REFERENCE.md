## 实际包含三个游戏

| 目录 | 玩法与呈现 | 实现依据 |
| --- | --- | --- |
| `pelican-bike` | 鹈鹕海岸骑行、收集鱼、昼夜与多种镜头；海面和围巾等动态细节 | `src/main.js`、`pelican.js`、`ocean.js`、`world.js` 等；package 的 Three.js 为 `^0.186.0`。 |
| `cf-transport-ship` | 运输船团队 FPS、电脑对手、武器操作与命中反馈；货柜甲板、海洋与光照环境 | `src/game.js`、`player.js`、`map.js`、`env.js` 等；package 的 Three.js 为 `^0.186.0`。 |
| `qq-speed` | 六车竞速，四种赛道主题，漂移、氮气、小喷、跳跃、道具及触屏 | `src/vehicle.js`、`track.js`、`maps.js`、`layouts.js`、`ai.js` 等；lock 实际为 Three.js **0.169.0**、esbuild **0.28.2**。 |

三个工程均以 Three.js 绘制三维场景，主要使用程序化几何、Canvas 纹理及 WebAudio 音效，esbuild 将代码内联进 HTML。上游 README 的“单次生成”“完整自测”等说法是作者自述，本次调查没有独立验证那些开发过程。

## 与本作有关的参考点

QQ 例包含一个玩家和五个 AI，车头方向与移动方向分开计算，以抓地变化体现漂移；采用固定步长、闭合赛道、追尾镜头、排名/圈数/小地图和氮气反馈。菜单提供地图、车辆配色、模式、圈数、难度和画质选择。其视觉以低多边形赛车和环境、宽路面、路肩、护栏、烟尘和加速效果构成。

霓虹飞车保留“完整三维竞赛、转向漂移、集气加速、电脑对手、不同节奏赛道和多输入方式”的体验目标，独立制作星港夜航、海风回廊和赤岩跃谷。为适应电视遥控器采用自动油门，固定六车两圈；不把上游的四张地图、八种配色或道具模式描述成本作已实现内容。

本作进一步使用顺序检查点与正向穿越检查，明确区分真实松手和输入取消。原例的玩家圈数检查包含起点跨越及半圈标志，本作没有复制这套判断。

## 许可调查

GitHub API 返回根仓库 `license:null`，文件树中没有单独 LICENSE。QQ 与鹈鹕的 package 元数据声明 ISC，不能据此说“整个仓库没有任何许可声明”；运输船 package 未声明项目许可。QQ 锁定的 Three.js 和 esbuild 为 MIT。这些是参考项目的信息，本作的原创代码与实际依赖许可另见 [NOTICE.md](../NOTICE.md)。

## 本次对参考游戏做过的检查

QQ 例的 `npm ci --omit=dev` 与 `node build.mjs` 成功，产生约 700 KiB 的单 HTML。以系统 Chromium、1280×720 视口和 SwiftShader 加载本地 HTTP 页面，实际看到三维城市背景及菜单；菜单开始按钮底部贴近并部分超出可见区域。此截图只用于调查，没有作为本作预览或随本目录复制。

参考例高画质开始后，等待进入比赛状态 30 秒超时。随后通过普通菜单改为流畅档，等待 60 秒仍停在倒计时，内部倒数累计约 1.0817 秒，未捕获页面脚本错误。因此本次只确认参考例能构建且菜单可见，**没有宣称驾车或完整比赛验证通过**。这是本次软件渲染环境的观察，不能推广为真实 GPU 的性能结论。

最初使用 `file://` 被环境浏览器策略拒绝，改用限定在参考构建目录的本地 HTTP 服务后可以加载。参考检查的两个临时服务与浏览器均已关闭。另两个游戏没有在本次调查中实际运行。
