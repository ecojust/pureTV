# 霓虹飞车实现与验收约定

本作将比赛规则、赛道数据、三维呈现和输入宿主分开。此文对应当前源码结构；测试是否通过、冻结提交、录像及最终 APK 来源以实际发布记录为准，不从实现说明推算验收结果。

## 比赛与车辆

[model.mjs](../source/model.mjs) 提供 `create(seed, difficulty)` 和 `step(state, dt, input)`。`difficulty` 在本作中选择三条赛道，不代表额外的难度菜单。状态是可序列化的普通数据，含三秒倒数、两圈目标、一个玩家和五名电脑对手、排名、比赛计时与漂移/氮气/碰撞/跳跃统计。玩家完成两圈进入完赛状态，名次单独显示；比赛计时到 180 秒仍未完成则结束。终局不继续推进模型。

车辆具有世界坐标、车头航向 `yaw`、速度方向 `velocityYaw` 和速度。转向输入改变车头，抓地力决定移动方向跟随车头的速度，漂移降低抓地并产生侧滑。玩家没有沿中心线自动转弯的逻辑；自动油门只处理纵向加速，撞到护栏会限位和减速，不会替玩家把车头转过下一个弯。

五个 AI 通过前方路线和曲率产生转向、刹车、漂移与氮气输入，再进入与玩家相同的车辆推进和碰撞逻辑。它们是本地电脑对手，不是网络真人。随机种子使其初始差异可复查。模型内部将步进拆成不大于 1/120 秒的小步，减少低帧率时跨过护栏、加速带或检查点的风险。

漂移要求车速、实际转向、地面接触和侧滑满足条件才积气。保持有效漂移后，真实松开动作键可获得短暂小喷；刹车或取消输入不产生松手奖励。氮气消耗整槽储备，并用按下边沿触发，避免持续按住重复释放。加速带和跳台由真实经过对应路段触发，同圈同设施有访问记录。跳跃使用独立高度和重力，落地后才可能获得落地小喷。

## 一个几何来源

[tracks.mjs](../source/tracks.mjs) 独立于 Three.js，保存三条原创路线。当前路线由直段和圆角弧段构成，再结合周期起伏与跳台高程，生成 768 个带距离、航向、曲率和宽度的采样点。它不是对上游 Catmull-Rom 控制点或官方地图的复制。

`sampleTrack(track, s)` 根据沿路距离采样；`projectTrack(track, x, z, hintS)` 将世界坐标投影回赛道并返回横向偏移。车辆、AI、路面/护栏、设施、起点、小地图和镜头前方观察共用这些接口。渲染器不能另造一条看似相同的路线，否则画面与碰撞边界容易分离。

每圈分为八个顺序检查点。累计进度只接受与本步车速/时间相符的投影位移，只有正向跨越下一检查点才增加通过数；跨终点前必须先完成整圈顺序。逆行、来回跨起点、异常坐标跳变以及复位不直接授予圈数或前进距离。复位回到记录的安全点，清除速度/漂移/跳跃，并限制恢复初期速度；模型保留该能力用于异常恢复，玩家的 `R` 键是重开整局。

## 输入、暂停与取消

继续使用 Game Kit 的 `x/y/a/bPressed/cancelled/cancelEpoch` 输入。自动油门使方向键和左侧手机摇杆可以专注转向，下方向为刹车；A 按住漂移，B 边沿释放氮气。`source/game.mjs` 将 Shift 映射为空格动作、Ctrl 映射为 B，并提供本地触屏按钮。遥控器确认键只在本作声明的 `holdConfirmAsA` 模式中充当持续漂移。

失焦、后台、指针取消、手机断线或房间/会话变更会清理输入；运行时用取消标记和 epoch 把取消送到下一次实际模型步。模型清空未完成漂移信号，避免把系统清零误认成玩家漂亮出弯。按键隔离等待真实松开，随后才能接受新的动作。手机断线和用户暂停由宿主暂停比赛；暂停期间不调用规则步进，不积累计时或漂移奖励。

这些生命周期行为需要独立回归，不能仅用按键对象被清空证明它们正确。实际网页游玩和手机协议模拟分别保留证据，不能把合成手机快照称为实体手机测试。

## 两个可选宿主扩展

| 扩展 | 本作用途 | 边界 |
| --- | --- | --- |
| `GameDef.createRenderer(canvas)` | 为现有画布创建 `RushRenderer`，提供 `begin/end/dispose`、本作 `draw` 及实际绘制指标 | 只声明本 hook 的游戏选用它；其他游戏继续使用默认渲染器。渲染器不得修改比赛状态。 |
| `GameDef.afterUI(state, context)` | 更新小地图、漂移/氮气表、倒数、触屏控件、双语文案和声音 | 在共享界面更新后调用；不能跳过暂停、输入取消或原生手柄生命周期，也不能改变模型。 |

扩展位于 [Game Kit 运行时](../../../game-kit/web/runtime.js)，说明见 [Game Kit README](../../../game-kit/README.md)。本作样式、音效和附加控件仍由自己的 `source/game.mjs`、`audio.mjs` 与 `rush-theme.css` 管理。

## 图形与性能

[world.mjs](../source/world.mjs) 使用锁定的 Three.js 0.160.1，能够选择 WebGL1 上下文。车体/车轮/阴影/火焰和粒子使用实例化，静态景物按材质合批；路面与建筑纹理通过 Canvas 生成。当前关闭实时阴影，采用简化阴影，像素比固定为 1，避免在电视或软件渲染器上因高 DPI、阴影贴图和大量物件拖慢整个比赛。

镜头平滑和视场变化只影响呈现。漂移烟尘和氮气火焰读取模型状态；绘制不推动圈数或计时。WebGL 初始化失败或上下文丢失显示明确提示，不把空画布称作成功的三维运行。

`metrics` 记录实际 WebGL 后端、draw calls、三角形、画布尺寸及资源数量；它们是诊断指标，不是帧率保证。SwiftShader 的软件渲染结果必须与真实电视 GPU、Android WebView 和实体手机测试分开，录屏输出为某一帧率也不代表游戏按那个帧率运行。严重掉帧时共享运行时会限制追赶步数，游戏计时可能落后于墙钟时间，应在记录中如实说明。

## 构建与证据

`npm run build` 将纯模型和游戏界面/Three.js 分别构建为本地 `game-model.js`、`game.js`，并复制自身 MIT 与 Three.js MIT 许可。`npm run build:check` 对照生成内容检查资产是否过期。`tools/prepare-web.py` 使用正式 Game Kit payload 逻辑导出浏览器目录，不维护另一套演示游戏；输出必须位于源码目录外。

验证应分别覆盖：模型规则和有限/确定状态；三赛道几何闭合、宽度与可通行性；顺序检查点、防逆行刷圈及复位；漂移、氮气、跳跃落地、取消和暂停；普通键盘/触屏输入完成比赛；960×540、1280×720 的控件、文字、侧栏和实际三维画面；最终签名包的资产和录像来源一致性。

`PureTVQA.snapshot()` 仅返回深拷贝观察数据，没有设置比赛状态的入口。自动驾驶测试策略可根据观察结果发出普通按键，不能写入模型、强制获胜或把手动推进时钟的协议测试冒充实际游玩。失败报告保留；冻结后改动须明确重跑哪些检查。下载包、签名、真实设备验证与源码公开分别记录，当前尚不在本文填写未完成结果。

停滞恢复：所有赛车在速度低于2 m/s持续4秒后回到最近安全点，计时不中断，进度只回退不增加；圈数与检查点不因恢复增加，复位后限速1.4秒。
