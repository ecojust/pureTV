# Pressure Seal — public interface and evidence

Status: canonical public specification accepted on 2026-11-02 after model, QA, independent and root static review. This is a specification, not evidence of implementation, play or performance. No private solution or hidden calibration route is included.

## Host integration

- Shared static host API: `resource/game-kit/web/runtime.js`. Its public model calls are `PureModel.create(seed,level)` and `PureModel.step(state,1/60,input)`; `GameDef.render` receives renderer, state, host elapsed and current host input. Model time is `state.tick*0.05`; host elapsed includes host substeps and is not proof of model dwell.
- `GameDef.seed=740`, scenario names STARTER/SWAP/HEAVY, `holdConfirmAsA=true`, and action labels HEAT + PUMP / VENT. The public `PureModel.config` is the sole pressure/material/scenario rule descriptor used by explanatory UI; do not duplicate different thresholds in art or code.
- Menu/result left-right navigation selects a scenario. Confirm/START starts it through the host. Retry uses host recreation; do not reset a subset of plant fields or patch an existing state. B during play is vent only. Pause remains a fixed independent host entry.
- Native phone snapshot supplies raw x/y/a/b/start/select plus phone identity/session/cancelSeq. Phone upper/lower right-third surfaces must maintain held booleans through multiple frames, allow A+B, release by pointerup, cancel by pointercancel/blur, and quarantine stale holds after reconnect/session/cancel-sequence changes. Menu joystick is selection only; no active-play hidden movement.
- Local keyboard and phone are combined by the host. A valid action from one source does not excuse another source's stale hold. Required clear-input paths include start, retry, pause/resume, browser blur/hidden, network change, phone disconnect/replacement and explicit cancellation.
- `PureTVQA.snapshot()` is observational only and returns host phase/paused/tick/elapsed/level, full model, renderer metrics, frame timings and connection status. `PureGame.key(name,down)` is the normal public keyboard event entry. Neither interface authorizes direct state mutation, direct hidden stepping, shadow-model search or force transitions.

## Truthful visible values

Active play must show current material/order, band low/high, numeric pressure, the 110 burst line, continuous `holdTicks*0.05 / requiredTicks*0.05`, heat, material safeHeat, and current dose/doseBudget. Distinguish current material damage from the retained warm heater. Show sealed materials from receipts. Show A/B activity separately and the next-neutral-tick release cue specified in public design. Failure text names exactly the model reason; final readings and completed seals remain visible.

Rounding is display-only. Pressure and heat may be shown with one decimal; dwell with one decimal and a monotone bar; dose as a percentage rounded upward and capped at 100%. The safe/target/burst lines come from exact public constants. Visual rounding cannot decide a hold, forgive a failure, fake an empty damage meter or advance a stage. A 100% rounded damage label below the exact limit must remain visually distinct from an actual settled OVERHEAT failure.

At 960×540, critical canvas words/numbers should be at least 24 logical pixels and ASCII in the baked glyph atlas. DOM instructions may use Chinese. The live controller regions must cover the right third above and below its midpoint; inspect the real hit regions, not merely the painted labels. Tests include centers, near-inner and near-outer edges, and the midpoint ownership rule.

## Public observations and receipts

Every ordinary browser/video run starts visibly from a menu/start or result/retry with a fresh model. Every ordinary model-only run records an actual public `create` call as a fresh `create` or `retry` origin; it cannot certify a visible menu or browser lifecycle. The observer records explicit `runId`, channel (`model` or `browser`), selected scenario/seed, origin kind, artifact-relative source identifiers, and a monotonically increasing observation sequence. These are evidence metadata outside the model; run IDs cannot replace model initial-state comparison. Every retry creates a new run ID and origin record.

For each sampled transition record the actual public input action and exact before/after snapshots, including host phase/paused/level/time when present, full model physics/counters/gates/receipts and source cancellation context available from real host input. For every model call record exact dt and each raw recognized input field before normalization, with missing fields distinguishable from false. Record both observed timestamps and model ticks. Preserve the original observation records; a review may append conclusions but must not rewrite them into a cleaner narrative.

- An independent adjacent-pair checker verifies one actual before/after pair at a time against public recurrence and gate/clock rules without importing implementation logic. Every calculation starts from that pair's actually observed before state; never roll a calculated after state forward as the next input state. Bind the reviewed source and trace hashes and state exactly which observed pair indices were directly checked.
- The ordinary model corpus may visibly call the public model API at `1/60` seconds, recording the actual before and after state of EVERY call, including calls with no physics tick but possible gate changes. Each such call crosses at most one logical tick. This is an explicitly recorded ordinary model run, separate from browser/video controls and synthetic boundary tests; it may not search, branch, inject state or conceal attempts.
- A pair spanning multiple logical ticks is sparse evidence unless the actual intermediate before/after states were also observed and retained. Even a complete input sequence does not authorize the checker to reconstruct intermediate states by recurrence replay. Mark an unobserved interval `not-observed` or `review-required`; do not retrospectively fill a dwell gap or call a sparse pair a continuous hold proof.
- Check `totalHeatDose=sum(sealed doses)+current dose` with only the model contract's audit-only regrouping tolerance; check integer counter/score identities exactly, ordered materialIndex/receipt changes, and no outcome duplication. Counters strengthen conservation checks; they do not turn unobserved intervals into observations.
- Every completed hold needs a continuous observed chain covering its required consecutive logical ticks, with both pressure endpoints of every tick in band and no failure or missing input interval. Entry from an outside endpoint earns no hold. A prior interruption from positive hold must visibly set hold to zero and increment `dwellResets`; a later seal must build a fresh complete hold.
- Lag evidence must include a real held-A release, gated command becoming neutral, positive heat at release, and adjacent observed post-release ticks with pressure still increasing under neutral A/B. A separate B-only interval should show pressure falling while heat persists.
- Pause evidence compares full plant/counters/remainder across actual host pause duration; no change is allowed. Gate fields should also remain unchanged while no model calls occur. Resume can update cancellation/gate fields, and subsequent active neutral ticks can coast normally. Retry snapshots compare every initial field, not only pressure. Distinct fresh-array reference identity needs a separately labeled model rule test; JSON snapshots alone cannot establish it.

## Public invalid/no-time boundaries

The model contract specifies terminal, invalid-duration and paused calls as exact no-ops. Rule tests may directly invoke those documented model APIs and use clearly labeled synthetic boundary fixtures. Such tests are separate from ordinary-run evidence and never substitute for visible start, actual controls, attainable outcomes, performance capture or gameplay video. Invalid inputs do not get a hidden time advance or resource award.

## Review and execution gates

Before any production implementation, the model author, QA author and independent auditor review all three public drafts and identify unresolved clock/input/damage/dwell/outcome/evidence questions. Root accepts the resulting public documents. Drafting prose is not permission to run a pilot, test model viability with a scratch simulation or execute a future implementation.

Before first use of any executable/helper, root reads its full current source; syntax/import checks count as execution. Preserve source hashes and review attestations. Ordinary pilots must be publicly reviewable action drivers, issue real input through allowed host/browser/phone channels, and expose all attempts and outcomes. They may use visible/public current observations to react; they must not run a shadow copy, inspect hidden future states, search private trajectories, inject state, silently calibrate, or hide failed/warmup attempts.

Required later acceptance covers model rules, real browser controls including cancellation and phone hit surfaces, independent evidence audit, visually reviewed original captures, measured performance and bounded histories, APK/source/asset identity and size, genuine decoded gameplay capture and its size, and the per-game pushed commit. No game is counted complete from these drafts or from a passing static review alone.
