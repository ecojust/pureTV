# 棋盘生成与约束边界

采用标准 Hitori 三条规则：白格在行列内数字不重复、黑格正交不相邻、白格形成一个非空正交连通块。数字由公开网格给出；生成阶段可使用候选黑格形状，但生产资产只保留数字，不带解或期望涂黑数量。

设计时核对“4×4 且至少六个黑格”的题量目标，发现它与后两条标准规则不兼容。完整枚举全部 **65,536** 种4×4黑白形状，满足黑格不相邻及白格连通的数量如下：

| 黑格数 | 合法形状数 |
| --- | --- |
| 0 | 1 |
| 1 | 16 |
| 2 | 92 |
| 3 | 224 |
| 4 | 193 |
| 5 | 36 |
| 6–16 | 0 |

因此保留4×4／5×5／6×6的渐进尺寸，首关采用五个黑格，后两关分别七个、十个。没有放宽连通或相邻规则来凑数量。此调整仅解决不可实现的内容量条件，不改变玩法。

生成先构造黑格不相邻且白格连通的候选形状，再从打乱的拉丁方保留白格数字，给候选黑格配置同行／同列的重复值。随后独立约束搜索重新求解完整数字盘，而非直接接受生成掩码。搜索对重复数字对施加“至少一黑”，对相邻格施加“至少一白”，传播后分支枚举，并用白格连通性筛掉不合法赋值。

三关恰有一个合法解，黑格数5／7／10。自行测试和独立 QA 均应从公开数字重新求解；求解器只在 tests 中。几何边界、唯一性和普通输入通关是不同证据，不把静态可解声明当作实际游玩结果。尚未验收的浏览器、正式签名及硬件状态由对应报告记录。
