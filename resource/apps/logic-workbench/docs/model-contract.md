# Pure model contract

Exports only create(seed,level), step(state,dt,input), deeply frozen config. Defaultseed800/level0. Input names A/B/C and gateNames EMPTY/AND/OR/XOR/NOT are public. Layouts contain only id/name/nameZh, slots `{a,b}` and eight target bits. Reference0=A,1=B,2=C,3=G1,4=G2 etc; each source is strictly earlier than its slot. Both sources are distinct. Final slot is output; state.outputRef=slots.length+2. No solution assignments, solver, distance tables or authored route comparisons in production.

State copies slots/target, gates initialized0, selectedSlot0 and selectedRow0. Gates0empty,1AND,2OR,3XOR,4NOT. truthRows eight entries contain `{row,inputs,signals,gateOutputs,output,target}`; row bits are A=(row>>2)&1,B=(row>>1)&1,C=row&1. Signals begins with three inputs, then each gate's actual scalar0/1/null output. For a binary gate, either required null input makes null even for0 AND null; this is explicit unconfigured-signal propagation, not a claim of full symbolic simplification. NOT requires only first input; second ignored even if unknown. Empty outputs null. Actual complete gate results use ordinary Boolean operations.

Derived emptySlots/emptyCount/complete, outputs, matches and matchCount are refreshed after A. Left/right clamps selectedSlot; up/down clamps selectedRow0..7; navigation only changes view. A cycles gate0→1→2→3→4→0, increments edits/editVersion and invalidates lastCheckCurrent without discarding lastCheck. No auto-win.

B reports complete, matched (complete and eight matches), matches array, matchCount, failingRows ascending, firstFailure `{row,inputs,target,actual}` or null, emptySlots, outputs, per-row gateOutputs, editVersion and charged. All arrays are detached. If any empty slot, increments incompleteChecks only, free hint; checks/attempts/checkReceipts unchanged. Complete checks increment checks, decrement attemptsLeft and append `{gates,result}`. Matched wins before exhausted-attempt loss; thus correct third wins. Third complete mismatch loses reason `checks`. Terminal score100/0 and detached terminalReceipt; all future calls freeze exactly.

Config targets are nonconstant and functionally depend on all three inputs. Test-only exhaustive counts4^4/4^5/4^6 yield1/1/1 solutions and minimum3 distinct real types each. For every solution and every slot, all3 other real gate types and all4 replacements constant0/constant1/first-input/second-input change at least one target bit. This is stronger than merely being a structural ancestor. Such intervention/equivalence search is not a runtime feature and no precomputed solution is shipped.
