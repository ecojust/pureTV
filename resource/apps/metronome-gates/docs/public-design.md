# 节拍闸道 · Metronome Gates — 公开玩法

本文件定义公开地图、目标和玩法，不含预设输入路线或逐 tick 操作脚本。

## 玩家要做什么

蓝色玻璃球在机械庭院中收集所有标记，然后进入出口。球只在全局拍点走一格；方向不会让球在两拍之间移动。先看门牌的二拍/三拍周期与下一拍状态，再把方向和等待排进最多 6 项的队列。每拍取队首；空队也会原地等一拍并消耗预算。闭门是致命的进入错误，陷阱立即失败，墙只挡住这一拍。

方向 fresh 直接入队；A 放入一拍等待；B 只撤销尚未执行的队尾。方向必须回中后才能再次输入，长按不连发。按固定独立暂停入口暂停；恢复保留位置、队列、门拍号及距下一拍的余量。取消或连接输入 epoch 改变保留队列，但新输入须先完整回中。此输入隔离不等于暂停，不停止拍钟。

同一 tick 的顺序公开固定为 **B 撤尾 → 方向入队 → A 等待入队 → 拍钟推进 → 若到拍点则取队首并结算**。所以恰好在拍点到来的新命令可能本拍执行；满队拒绝不会自动覆盖旧命令。站在门格上时门随后关闭不会夹伤球，只有进入目标门格时检查开闭。

## 共享数据

- 身份：id 37，slug `metronome-gates`，包名 `com.ecojust.metronomegatestv`，seed 737，版本 0.1.0 / code 1。
- 逻辑画布 960×540；地图均为 13 列×11 行。坐标从左上 `(0,0)` 开始，x 向右、y 向下。下列每行就是对应 y 的 13 个格子。
- 固定逻辑 60 Hz；每拍 72 tick，即 1.2 秒。创建时 beatNo=0，首个执行拍是 1；每个门都使用同一个绝对 beatNo，无独立门时钟或隐藏 offset。
- 门开放当且仅当 `beatNo % period` 位于表中的 `openResidues`。门牌必须显示周期、开放余数、当前拍与下一拍开闭，且可预览接下来的最多 6 个预算内拍点。
- 图例：`#`墙、`.`地面、`S`起点、`E`出口、`M`标记、`X`陷阱、`a`…`h`门。所有非墙均可作为方向目标；闭门与陷阱有独立终局规则。门/标记/出口/起点不重叠。

## 场景 1：双桥庭院

`scenarioId=metronome-gates-1`，difficulty 0，预算 48 拍（57.6 秒上限）。起点 `(1,1)`，出口 `(3,1)`；标记 `m1=(11,1), m2=(11,9), m3=(1,9)`；陷阱 `(3,2),(9,8)`。

环形地形让玩家先理解队列、提前到过出口不算赢，以及同一个全局拍号下的两种门周期。完整收集的几何最短移动数为 34；存在无需重复绕圈的合法完成安排，最多再用 6 拍处理门相位。因此成功时长约 40.8–48 秒，留有少量纠错空间。该说明是公开布局的可行性界限，不是推荐动作序列。

## 画面与读图要求

浅石板、铜绿机械门拱、钴蓝玻璃球；以连续面、烘焙阴影和少量几何表现质感，避免像素外观和上一款织机的视觉结构。三图分别表现庭院、采样支路、十字闸室，同一套门和地台资产即可批绘，目标一张 atlas、单一主要 draw call；实测后才能声称性能达标。

完整地图始终可读，不依赖滚屏。实际球、尚未执行的六格队列、下一拍倒计时、已收集标记、出口锁定与剩余拍数各自清晰。门必须同时有字母、2/3 周期数字和开闭形状，不能只靠颜色；当前与下一拍不能共用一个含糊的灯。球只在实际结算边界换格，不用提前插值伪造移动。可以画拍点光晕和门拱变化，但不能改模型位置。

开始页讲清队列、A 等待、B 撤尾、闭门判入及预算；暂停、继续、胜负、重试使用宿主固定入口。重试精确重置本图的拍号、位置、标记、队列和输入闩，不改变地图或门相位。手机沿用真实通用摇杆与 A/B 大操作区，不宣称需要修改共享 controller 才成立。
