# Loop Orchard model contract

UMD `PureModel` exports only `create(seed=1,difficulty=0)`, `step(state,dt,input)` and `TICK_HZ=60`. Three fixed, fully public puzzles share a 4×4 vertex grid, its 24 adjacent unit edges, nine square plots, and 16 unique physical pipe instances. Retry restores the same public board. Production stores only initial public roles/clues; there is no solver, reference loop, author witness or forced outcome.

## One cycle, public clues and node roles

A placed pipe occupies one whole horizontal or vertical edge between adjacent grid vertices. Each edge has at most one pipe. Removing it immediately removes that adjacency and returns the same physical pipe ID. No diagonal or partial edge exists.

Each vertex is a neutral junction, a required tree, or a forbidden flower. Required-tree coverage means the vertex currently has at least one incident selected edge; it does not claim water is already flowing. Touching a forbidden flower means any incident selected edge and is forbidden at acceptance. A flower merely enclosed geometrically without touching its vertex is not a violation. Tree and flower roles are disjoint. Unused neutral vertices are allowed.

The active graph contains selected edges and vertices with degree>0. Its component count excludes every unused isolated vertex. A single closed loop requires a nonempty graph, exactly one active component, and degree exactly two at every active vertex. Thus two disjoint closed rings fail even though every used vertex has degree two. “One loop” means one connected cycle, not a uniquely solvable puzzle: every arrangement satisfying the actual rules is accepted.

Each plot lists its four distinct boundary edges in top/right/bottom/left order. `selectedCount` counts selected edges in that list exactly once. An interior edge contributes once to each adjacent plot; an outer-grid edge contributes only to its one adjacent plot. A turn along two sides of a plot counts as two segments, just as any other two selected boundary segments do. Numeric clues, including zero, require exact equality. `clue:null` explicitly means no hint and no constraint for that plot; render it as — / NO CLUE, never as numeric zero or as an already-satisfied green clue. All three puzzles use this same rule.

Acceptance requires singleLoop, every required tree covered, no forbidden flower touched and every numeric plot clue satisfied. Unused stock is allowed: consuming all 16 pipes is not a goal. PUMP is a separate control focus, not a source vertex. A ready drawing never wins automatically and no simulated water flow occurs before an accepted explicit PUMP submission.

## Geometry and public schema

Canvas is 960×540. `grid={cols:4,rows:4,x:156,y:102,spacing:108}` defines vertex centers `(156+col*108,102+row*108)`. Vertex IDs V1…V16 are row-major. Edge IDs E1…E12 are horizontal, iterating rows 0…3 and columns 0…2; E13…E24 are vertical, iterating rows 0…2 and columns 0…3. An edge focus is its exact segment midpoint. Plot IDs R1…R9 are row-major with centers halfway between their four corner vertices. `pump={id:'pump',kind:'submit',x:790,y:414}` is the independent submit focus.

- `vertices[]`: `{id,col,row,x,y,role,degree,incidentEdgeIds,componentId,onPipe}`. role is junction, tree or flower. incidentEdgeIds contains only currently selected incident edges, in edges-array order; it is not a list of every possible adjacent edge. componentId is null for unused vertices and is the first vertex in vertices/row-major order belonging to each active component. onPipe means degree>0, not successful watering.
- `edges[]`: `{id,aId,bId,orientation,x,y,plotIds,selected,pipeId}`. Endpoints are vertex IDs, orientation is horizontal/vertical, x/y are the midpoint, and plotIds names the one or two incident plots. selected is pipeId!==null.
- `plots[]`: `{id,col,row,x,y,boundaryEdgeIds,clue,selectedCount,matched}`. clue is an integer 0…4 or null. matched is null for an unhinted plot and otherwise the exact-equality boolean. Missing hints do not increase matchedClueCount.
- `pipes[]`: `{id,edgeId}`, with distinct IDs P1…P16 and edgeId null when free. `pipeStock=16`, `pipeCount`, `pipesRemaining`, `availablePipeIds[]` are current inventory. Free IDs remain in pipes-array order (numeric ID order). Every pipe is in exactly one of available stock or one edge, never both.
- `components[]`: `{id,vertexIds,edgeIds}` for actual active components, ordered by their representative's vertices-array position. Each vertexIds list follows vertices-array order and each edgeIds list follows edges-array order, independent of traversal order. `activeVertexCount`, `componentCount`, `leakIds` (degree 1), `branchIds` (degree≥3), `degreeTwo` (nonempty and every active degree 2), and `singleLoop` are public derived graph facts. leakIds and branchIds likewise follow vertices-array order.
- `requiredTreeIds[]`, `forbiddenFlowerIds[]`, `treesCovered`, `allTreesCovered`, `flowerTouchedIds[]`, `flowersAvoided`, `clueCount`, `matchedClueCount`, `allCluesMet` and `goalReady` expose the remaining requirements. goalReady is singleLoop && allTreesCovered && flowersAvoided && allCluesMet.
- `checks={hasPipes,degreeTwo,singleLoop,trees,flowers,clues}` contains the corresponding current booleans for the PUMP panel.
- `focusItems[]` is edges-array order followed by pump, each `{id,kind,x,y}`; kind is edge or submit. `selectedId` begins at E1, and `cursor` is a copy of the actual focus item. There is no held tile or preview reservation in this game.
- `history[]` contains copied committed edit records `{kind,edgeId,beforePipeId,afterPipeId,at,tick}`. kind is place or remove. Each record changes exactly one edge; before/after IDs allow precise LIFO reversal. `historyDepth` is its length. `totalEdits`, `placements`, `removals`, `undos`, `editAttempts` and `blockedPlacements` are lifetime counters. editAttempts counts only A-on-edge attempts, excluding PUMP submissions and B actions. totalEdits===placements+removals===historyDepth+undos and editAttempts===totalEdits+blockedPlacements on ordinary states. The fixed 90-second clock bounds history to at most 5,399 edits without an extra gameplay cap.
- `lastEdit` is null or a detached copy of the latest committed edit. `lastUndo` is null or `{edit,at,tick}` with its own copied edit. Undo does not mutate prior feedback. `lastAction` and `events[]` describe real public actions; events reset each outer step and are capped at 32.
- `submissions`, `mistakes`, `maxMistakes=3` and `lastSubmission`. The latter is null or `{id,accepted,reason,selectedEdgeIds,pipeAssignments,checks,componentCount,at,tick}`. id is the incremented positive integer submissions count. selectedEdgeIds and pipeAssignments (`{edgeId,pipeId}`) are independent copies in edges-array order. pipeAssignments contains only selected edges with non-null pipe IDs, never empty edge entries. checks is also copied. reason is accepted, empty, branch, leak, multiple-loops, trees, flower or clues.
- `width,height,seed,level` (1…3), `difficulty` (0…2), `levelName`, `phase` (playing/won/lost), `tick`, `elapsed=tick/60`, `timeLimit=90`, `remaining`, `score`, `message`, and `lostReason` (null, mistakes or timeout).

## Editing, exact physical inventory and submission

Initially all edges are empty, all 16 pipe instances are free and edit history is empty. Directions navigate actual edge midpoints plus the independent PUMP focus. Eligible items lie strictly forward on the chosen screen axis. For displacement dx,dy use cost `dx²+dy²+2*perpendicular²`, where perpendicular is dy for horizontal input and dx for vertical input. Choose minimum cost, then squared distance, absolute perpendicular displacement and focusItems array index. No eligible item leaves focus unchanged. The fixed 25-focus graph is verified strongly connected.

A on an empty edge places the lowest-numbered currently free pipe. A on an occupied edge removes its current pipe and returns that exact ID. Both successful actions add one history record and update all graph, role and clue facts atomically. Any of the 24 edges may be drawn, including an edge touching a flower or creating a leak/branch; those violations are visible and rejected by PUMP. If an empty edge is selected while stock is exhausted, A reports stock exhaustion without changing geometry, history or mistake count; it increases editAttempts and blockedPlacements only. Removal remains available with zero free pipes.

B reverses the most recent successful edit: undoing a placement returns its recorded pipe, while undoing a removal restores the same original pipe to the same edge. LIFO order guarantees that restored pipe is available. Other edges are unchanged. Rebuild all inventory locations, incident lists, components and plot counts immediately; an isolated vertex left by removal has degree zero, empty incident list and componentId null. Focus returns to the edited edge. With no history, B is a harmless no-op. Undo never refunds time, submissions, mistakes, totalEdits, placements or removals. A failed stock attempt is not undoable history. Terminal states cannot be undone; shared retry creates a fresh identical puzzle.

A on PUMP explicitly submits without changing any pipe assignment. Diagnostic priority is: empty drawing; any branch; any leak; multiple closed components; missing required tree; forbidden-flower contact; wrong numeric clue; otherwise accepted. All current checks remain publicly visible even when only the first failure is the headline. Each fresh rejected PUMP press increments mistakes; the third loses. Held A does not repeat. A correct PUMP submission wins with any amount of unused stock. Rendering may highlight accepted irrigation only after phase=won; a previously rejected or unsubmitted partial graph must not be depicted as successful water flow.

## Fixed clock and score

Each fixed tick first advances the active clock and loses at elapsed≥90 before any action, including a winning PUMP press or an undo. Pending B then has priority and discards simultaneous A and navigation on that tick. Otherwise navigation precedes A on the resulting focus. Priority applies per tick: a held direction may act on later substeps of one larger-dt call after B. Direction uses the larger absolute axis, horizontal on ties, .25 deadzone, immediate new-direction movement, first held repeat after 20 ticks and subsequent repeats every 10. A/B are press-edge actions; zero/subtick dt may cache edges but does not edit or submit before a full tick. Coalesced button edges produce one action.

Finite dt is clamped to [0,.25] with a fixed 60 Hz accumulator. Cancellation-owned input or a changed cancelEpoch clears pending buttons/repeat and is neutral for that sample while time advances; it preserves selected focus, inventory, drawing and edit history. First epoch initializes normally. Shared pause freezes by not calling step. Terminal calls freeze every field, including history, events, selection and input bookkeeping.

Current score is `pipeCount*10+matchedClueCount*25+treesCovered*20`; winning adds `1000+floor(remaining)*5`. An initial numeric-zero clue can already contribute 25 points, so initial score is not assumed zero. Score is derived from the current public drawing, never from lifetime edit totals, and undo/rebuilding cannot accumulate repeatable points. Formal boundary fixtures and author example constructions are separate from public-only planner normal play evidence.

## Authored public boards and bounded feasibility

Plot clue arrays below are in R1…R9 row-major order; null is an explicitly unhinted region. Roles refer to the V1…V16 vertex IDs defined above. All unlisted vertices are neutral junctions. Each board starts with zero placed pipes and, for these particular clues, score zero.

Authoring enumerates every canonical simple cycle in the fixed grid: 213 cycles, with lengths 4/6/8/10/12/14/16 occurring 9/12/26/52/76/32/6 times. It also enumerates 87 vertex-disjoint double-cycle drawings, 20 triple-cycle drawings and one quadruple-cycle drawing. No single-cycle clue signature equals any multi-cycle signature when all nine plot clues are given. Across all 18,531 single/double pairs, one omitted clue is the exact minimum needed to admit a topology-only counterexample, including the requirements of at least two common trees and at least one common avoided flower.

The three public boards each have eight numeric clues and exactly one null, one valid single-cycle solution, and one double-cycle drawing that meets every numeric clue, role requirement, stock limit and degree-two condition. The valid single cycles use 8/10/10 pipes; the double-cycle counterexamples use 12/14/14, so unused stock cannot be treated as failure. There are no triple/quadruple-cycle local counterexamples for these boards. Full public boards are pairwise distinct under rotations/reflections; the second and third share a clue-only symmetry class but have different required-tree sets/counts and forbidden roles. The fixed 25-focus navigation graph is strongly connected, with maximum shortest navigation distance 10. Reference edges and witness paths stay in scratch/tests rather than production.
