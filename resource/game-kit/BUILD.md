# Shared APK host and signing

Every game has its own `resource/apps/<slug>/game.json` and `src/main/assets/`.
The shared Java package is `com.ecojust.gamekit`; `packageName` in each game's
metadata is the independent installed Android application ID.

Required metadata: `id`, `name`, `nameEn`, `packageName`, `version` and
`versionCode`. Optional phone labels are `actionA`, `actionAEn`, `actionB`,
`actionBEn`. `actions: 1` gives A the complete right third; the default two
actions divide that region into upper and lower halves.

Shared `web/*` and the game's assets must have different, top-level filenames.
`game-config.json` and `assets-index.json` are generated by the builder. Do not
provide those files manually. Only indexed TV assets are served to the native
bridge origin. The phone can load only its controller files and public config.

```sh
python3 resource/game-kit/build.py \
  --game resource/apps/gravity-courier \
  --output /workspace/scratch/hundred-games/gravity-courier/build
```

The local defaults use the installed scratch SDK/JDK/ZXing cache. Elsewhere,
pass `--sdk`, `--jdk`, and `--zxing`; SDK API 35/build-tools 34.0.0, JDK 17 and
the pinned ZXing 3.5.3 jar are required. `--cache` selects the shared dex cache.
Outputs are `unsigned.apk` and `build-receipt.json`. Both local and signed APKs
must be strictly below **10,000,000 bytes**. The builder never creates a key or
signs an APK, and never changes an existing game or publication index.

Native calls use `PureGameHost.getInfo()/snapshot()/publish()/exit()`. The TV
runtime receives `PureGame.key(name, down)` and `PureGame.suspend(boolean)`.
The single-player LAN transport authenticates room/session tokens, bounds
clients and messages, clears stale input after 750 ms, retains quick taps and
resumes the same seat for 15 seconds. Phone input fields are `x/y`, `aimX/aimY`,
`a/b/start/select`, `cancelSeq`, and increasing `seq`. The phone deliberately
uses touch steering and does not advertise unimplemented motion control.

Run the shared host regressions after changes to native code:

```sh
cd resource/game-kit/android
JAVA_HOME=/workspace/scratch/usedcar-local-https/jdk-17.0.21+9 \
ANDROID_HOME=/workspace/scratch/usedcar-android-sdk \
GRADLE_USER_HOME=/workspace/scratch/usedcar-gradle \
/workspace/scratch/usedcar-local-https/gradle-8.9/bin/gradle \
  --offline --no-daemon testDebugUnitTest lintDebug
```

`node resource/game-kit/controller-test.mjs` loads the real phone page in
Chromium and tests a simulated LAN peer, multi-touch, edge zones, cancellation,
background/reconnect handling and selection prevention. Its results are
browser tests, not claims of physical-phone/TV validation. Every game's own
model, full TV flow, performance and gameplay recording require separate tests.

## Signing one completed game

The root workflow owner commits the exact source to a reviewable source ref,
rebuilds that source locally, then creates request files:

```sh
python3 resource/game-kit/prepare-signing-request.py \
  --build /workspace/scratch/hundred-games/gravity-courier/build \
  --source-sha EXACT_40_CHARACTER_SOURCE_SHA \
  --output /path/to/request-worktree
```

Commit only `requests/<slug>/request.json` and `unsigned.apk` to a branch named
`build-assets/game-kit-requests-SESSION`. Dispatch `sign-game-kit.yml` with that
branch, the exact `source_sha`, and `slug`. This file-writing helper neither
commits nor pushes nor dispatches anything.

The workflow runs once (20-minute cap). It checks out the signing tools at the
workflow commit and the game at the requested exact SHA. The pinned builder
compiles the source's Java/resources/assets without executing source Python,
Gradle or shell scripts. The request's package, version, digest, size and exact
asset bytes are checked. The workflow **always signs the fresh CI build**, never
native bytecode supplied by the request. `localBuildMatchesCi` records a complete
ZIP-entry comparison; toolchain differences cannot bypass source validation.

Only the signing step receives existing `PURETV_KEYSTORE_BASE64` and
`PURETV_KEYSTORE_PASSWORD` secrets. It checks the certificate against
`tools/puretv-release-certificate-v2.sha256`, signs through password environment
references, verifies the finished APK and removes the temporary key. The only
deliverable is Actions artifact `game-kit-signed-<slug>-<source_sha>`, containing
the signed APK and `signing-receipt.json` with source/native/asset hashes and the
public certificate fingerprint. The workflow has no repository write
permission and changes no branch, GitHub Release or Gitee publication.

The root owner downloads and verifies this artifact before the individual
game's final commit/push. Do not count the unsigned local build as a published,
installable release.
