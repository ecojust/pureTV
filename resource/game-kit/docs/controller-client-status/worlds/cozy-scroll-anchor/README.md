# Cozy：聚焦 Music 后插入手柄卡片的滚动修正

上一公开版为0.5.3；本目录比较的0.5.4均为本轮尚未发布的候选产物，不代表已公开发布。

802 已签名候选包（0.5.4，尚未发布）的 Android 图显示：Music 位于原滚动侧栏底部并保持焦点，连接卡片插入顶部后浏览器滚动锚定将侧栏向下滚动；sticky 卡片继续停留顶部，盖住品牌和二维码。此前未聚焦 Music 且无真实二维码的通用布局检查未覆盖这个组合；它不能替代本次专项。

产品修正仅 `tv.html` / `tv.css`：连接卡片和 Music 位于滚动区外；二维码、玩家与帮助位于独立的 `.sidebar-content`；关闭侧栏滚动锚定。主游戏区域、画布、模型、runtime、原生输入与其余游戏均保持不变。`asset-diff.json` 对比802 已签名候选包 和新准备资产，只有这两份 UI 文件不同。

## 保留的证据

- `original-package.json`：802 已签名候选包、原 Android 报告路径及 SHA256。802 候选包 通过 `tools/readme-controller-qa/prepare-assets.py --apk ...` 解包。
- `attempt-1-before/`：802 候选包 完整资产、实际二维码尺寸，普通 Tab 聚焦 Music 后连接单/双手柄。960 的 scrollTop 为 0 → 26 → 104 → 178，双席二维码被盖；1280 为 0 → 15 → 76 → 134，双席同样盖到二维码。此轮是复现采集，`observe/passed` 仅表示采集完成，不表示布局通过。
- `attempt-2-css-only/`：只加 `overflow-anchor:none`，960 的 scrollTop 固定在26，但卡片仍覆盖品牌，断言失败，故未采用这个单独修正。
- `attempt-3-tab-order/`：结构修正后 Chromium 将独立可滚动区域纳入 Tab 顺序，脚本“单次 Tab 必达 Music”的假设超时；原截图和脚本保留。后续按普通 Tab 顺序走到 Music，没有修改产品来迁就此假设。
- `attempt-4-final-focus/`：两分辨率各8个状态采样全部通过，记录原候选和新资产的画布/主游戏区域矩形，全部相同。聚焦Music后连接单/双手柄，内外scrollTop均保持0、二维码矩阵全见；真实鼠标滚动详情后卡片与Music固定且不相交，滚回顶部二维码恢复完整，Music可点击切换。两种尺寸的双席与滚动截图已目视。
- `attempt-5-layout/`：仅 Cozy 的 960×540 / 1280×720 通用布局补验2/2场、28项通过，包含菜单、实际游玩、暂停、96字符ID、断线/重连与本地键盘边界；每种尺寸3张代表截图已目视。其它3D游戏未重跑。

最终摘要见 `final-summary.json`：聚焦专项2/2（16个状态采样）与通用布局2/2（28项）均通过，资产SHA与冻结后的工作区一致。最终源 `tv.css` SHA256为 `b2a6f1949e6ed471b0faf2b32ab3b8cbee3cb4a405bc8f26a58bc77bea0a93ae`，`tv.html`为 `28b9c1c3b364f5239721f3b5829a6dd8194b1459c54c12bd9dfb9600b8ac0fcf`。

`focus-check.mjs` 使用实际准备资产、802 候选包 的二维码房间信息和明确标记的合成原生连接快照，验证焦点、滚动、矩形相交与操作；没有真实 SDK/TCP、Android 或实体设备声明。所有截图记录 SHA256，原始报告保留。正常20字符ID需完整显示二维码矩阵；内部详情人为滚动时按实际裁剪区检查，外部卡片和Music仍必须完整可见。

房间信息夹具保留采集时的静态服务文案，合成原生快照仅驱动身份卡状态；这些截图不宣称真实联网或真实SDK状态同步。新签名候选包的原生状态验收由独立CI执行。
