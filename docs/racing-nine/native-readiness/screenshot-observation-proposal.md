# Bounded observation of an original macOS screenshot request

The original Turbo Kart Rush native ARM report from run 44605303936 / source b7b7af12f1eb61f777d89edad7368a69a14bb9e3 failed because `reconnected.png` was absent after the verifier's 20-second wait. Occupied-port ARM and Rosetta completed all nine checks. The final original native state remained active, paused, connected and error-free with advancing frame/poll counts; this does not identify why WKWebView did not produce the requested PNG. `native.log` was empty. The original host removes the request before `takeSnapshot`, silently ignores a PNG write failure, and does not report a nil-image/nil-error callback. These observations cannot prove a renderer hang or a successful snapshot callback.

Proposed first change is QA only, retaining the original application and package bytes:

- Modify only `joystick-games/tools/macos-verify.py` and its existing `joystick-games/shared/macos/tests/native-observation.test.py` coverage. Keep the normal settling delay and send one screenshot request. Increase its monotonic deadline from 20 to 60 seconds; do not reissue game inputs, mutate model state, retry gameplay or queue overlapping native snapshot requests.
- Write a bounded screenshot-observation journal before waiting, then record request-file consumption, actual PNG appearance/bytes/hash, process liveness and a compact fresh diagnostic summary once per second or on a meaningful transition. Include the original state timestamp, active/ready flags, renderer/frame/poll counters and the already exposed `diagnosticError` / `lastJavaScriptError`. Capture read/write/parse failures explicitly. Keep the full final original diagnostics file and normal report separate.
- Accept only a newly created, regular PNG for this exact request, with the PNG signature and existing minimum size requirement. Reject stale/pre-existing or symlinked output; do not use another mode's image. Preserve the current mandatory screenshot requirement and original failure if the deadline expires or the app exits.
- State `nativeCallbackObserved:false` / `hostCallbackReportingAvailable:false` for these original packages. Request consumption is not a callback acknowledgement. An exposed WK error may be recorded faithfully, but absence of an error is not success.
- Test bounded late arrival after 20 seconds but before 60, unchanged deadline failure, process exit, reported diagnostic error, stale/symlink/non-PNG rejection, and bounded journal size using a deterministic clock and filesystem fixtures. These are QA-observer tests, not new native gameplay evidence.

A separate future host change could write an atomic request-correlated native snapshot result containing callback arrival, image conversion and PNG write status/errors. It would require changing `shared/macos/Sources/main.swift`, rebuilding packages and new exact-source native tests. It must not be claimed for the original Turbo package. The first proposal does not change that host or expand Intel coverage.

After freezing the QA-only change, root may invoke the existing exact-package runtime verification once for the original Turbo package. The original native failed report and both original successful mode reports remain unchanged, and a successful retry is reported as a new QA attempt rather than replacing them.
