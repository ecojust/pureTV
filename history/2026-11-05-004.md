## 行动记录

### A1 · 故障定位

- 工作区干净，从已发布 0.5.1 的收尾提交建立修复分支；已阅读协作规范、工作索引及相关发布记录。
- 核心连接在 ADB status=device 后创建占位设备，扫描首先强制调用 `am get-current-user`。该命令不受电视系统支持时立即返回，导致型号、Android 版本和系统信息查询均未执行；刷新信息也受同一前置查询阻塞，符合用户提供的错误与界面状态。
- 正在检查兼容的当前用户探测和只读系统信息查询分离，并审查旧系统 HOME 查询能力。不会默认猜测 user 0 或放宽当前启动器保护。
- 两个只读 agent 分别核对 Android 命令兼容性与界面状态／测试入口。已异步询问型号及 Android 版本，独立修复工作继续进行。

### A2 · Android 4.4 源码核对与实现

- 用户确认 Android 4.4。直接核对 AOSP `android-4.4_r1`：其 `am` 没有当前用户命令，`dumpsys` 不打印 `mCurrentUserId`；`dumpsys activity processes` 的 `mUserLru` 则由源码明确保证最后一项为当前用户，切换时同锁更新。兼容回退严格限定实时 SDK 19，不泛化至未核实版本。
- 新增严格用户探测（am → cmd activity → SDK 19 的进程状态），无法确认时返回简短错误、保留拒写。设备在线核验与用户核验分离，扫描先读全局信息；手动刷新系统信息无需用户命令。
- 修复 4.4 `df` 不支持 `-k` 的第二个兼容问题，回退 `df /data` 并按明确表头和单位解析。既有内存与 CPU 旧属性回退保留；没有 HOME 查询能力时仍禁止停用／卸载，安装不会移除 `--user` 改成全用户操作。
- 新增相应核心回归；只读复核并行进行。Rust 最小工具链安装于仓库外 `/workspace/toolchains/rust-1.99.1`（官方哈希核验），测试将使用独立临时 target，未更改依赖或测试标准。
- 按 U3 新增离线 Info 页，覆盖每个操作的命令、参数与兼容限制，维护三语、主题、滚动及完整文案检查。准备将兼容修复与说明页一起交付 0.5.2 补丁；此前 0.5.1 标签和产物保留。
