# 用户请求与行动记录

本目录帮助后续 agent 从真实工作状态继续。先读 [INDEX.md](INDEX.md)，再读最新记录和相关未完成记录；同时核对 Git 状态及项目进度。

## 记录方式

- 文件名为 `YYYY-MM-DD-NNN.md`，日期采用 UTC，序号从 `001` 递增。同一持续任务可跨日期追加；新独立任务新建文件，并在索引登记。
- 每条用户 prompt 原样记录并编号，保留后续补充的顺序。没有保留下来的历史 prompt 明确写“原文不可得”，不得编造。
- 有意义的工作阶段后追加行动条目，说明实际变更、验证、证据和结果；最终回复前写清交接状态。发现之前判断有误时追加更正，保留原始过程。
- 状态使用 `in_progress`、`blocked`、`completed`、`cancelled`。`blocked` 写清具体缺项；只有本条请求的目标已完成才用 `completed`。完成第 48 款不代表百款计划完成。
- 持久文件使用仓库相对链接；外部提交或工作流使用完整链接；本次 scratch 路径标注“临时，后续环境可能不存在”。不要把绝对 workspace 路径作为唯一交接入口。
- 记录证据摘要，不复制巨大报告。记录的测试通过数量应来自实际执行；计划执行、执行中、失败和通过分别注明。
- 不保存秘密、完整敏感输出或私有推理。prompt 中秘密用 `[已脱敏：类型]` 替换并注明；非秘密文本保持原样。
- 多 agent 协作由主 agent 汇总；并行 agent 汇报自己的结果，避免同时改同一日志段落。

## 模板

```markdown
# YYYY-MM-DD · 任务名称

- 状态：in_progress
- 分支：实际分支
- 起点：实际提交 SHA
- 关联记录：无／相对链接
- 当前目标与边界：用户要求及本次实际范围

## 用户 prompt

### U1

> 用户可见原文；不得补写无法取得的历史原文

## 行动记录

### A1 · 阶段名称

- 动作与文件：实际做了什么。
- 决策摘要：为什么采用这个可复查的方案。
- 验证与结果：执行过的命令、退出结果、必要计数。
- 证据：仓库链接、提交／工作流，或注明临时路径。
- 限制与未完成：尚未验证、未提交或未发布的部分。

## 当前交接

- 已完成：已核实结果。
- 正在进行／阻塞：准确状态与缺项。
- 下一步：可直接执行的步骤。
- 发布状态：未签名／已签名／已推送；需要时附提交和工作流。
- 进度：计数的真实状态，避免提前增加。
```

`INDEX.md` 每行至少包含记录链接、状态、用户目标、当前结果与下一步。更新日志后同步索引，便于后续 agent 不必遍历所有旧记录。
