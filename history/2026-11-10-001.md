## 行动记录

### A1 · 核对归档与问题边界

- 从远程固定起点建立稀疏检出，工作树原本干净；读取 AGENTS、fork/MAINTENANCE 和原包归档历史。
- 用户报错路径中的 SHA256 与儿歌多多归档元数据一致；其 manifest 仅列出 `armeabi-v7a`，原始错误明确为 ABI 不匹配。
- 宝宝趣学 manifest 声明 `arm64-v8a`、`armeabi-v7a`、`x86`、`x86_64`，不能用儿歌多多的错误解释其闪退。
- 并行安排原包静态检查、儿歌多多可用来源核查，以及 APK Checker 独立 Linux TV 对照实验；实验尚未执行完成。
- 不改签、不替换原包。当前没有用户 Mac 的宝宝趣学崩溃日志。

### A2 · 静态核验、用户提示校正与可重建说明

- 儿歌多多8个原生库均为 ELF32 / EM_ARM；固定及当前上游仅有的1.3.0.0旧版也仅ARM32，不作为解决方案。
- 宝宝趣学有真实 ARM64 库，Manifest 仅普通 `LAUNCHER`，未声明 `LEANBACK_LAUNCHER`。业务代码使用加固壳，静态检查不足以判定崩溃根因。
- 找到与用户U3描述相符的 APK Checker 0.2.6 固定桌面说明，但尚未取得用户所见完整原文；不能据此认定启动失败。普通入口回退逻辑仍会继续启动应用。
- 新增按 APK SHA256 绑定的 `fork/compatibility.json`；生成器将兼容性说明同步到应用、分类及总目录，防止后续重新生成时丢失或套用给其他原包。APK字节、签名、图标、总数量不变。
- 静态证据归档至 [教育兼容性检查](../fork/verification/2026-11-10-education-compatibility/README.md)。
- APK Checker 独立诊断分支 `fix/education-apk-diagnostics` 提交 `d864145a7637a6501e7e282b48d599364d771410` 已推送；宝宝TV工作流 [42814114176](https://github.com/ecojust/apk-checker/actions/runs/42814114176)、儿歌TV工作流 [42814117728](https://github.com/ecojust/apk-checker/actions/runs/42814117728) 运行中，生产代码和发布版本未改。

### A3 · 真实失败对照与检查边界

- 首轮两次CI均为真实失败，无重试：儿歌安装 `NO_MATCHING_ABIS/-113`，当前用户无该包；宝宝安装成功、普通入口有效，启动后两条业务代码 NPE，分别在 `AndroidUtil.noBoxParseJson:22` 和 `UpdateManager.getRemoteVersionCode:3`。
- 设备为 Linux x86_64 / API36，实际 ABI `x86_64,arm64-v8a`；不能当作用户 Mac 已复现同一异常。宝宝已经实际执行，`apkExecuted` 更新为true，但不标记为运行通过；儿歌保持false。
- GitHub artifact下载403、job log接口为空，因此没有HTTP请求细节或已目视截图。完整未截断crash buffer、原始checks及阶段输出已归档，未以模糊错误猜测服务器停服。
- APK Checker证据提交 `a5188ef4547107b877c1b68dc04c41ac9222acce` 已推送；pureTV复制必要原始证据，见[运行对照](../fork/verification/2026-11-10-education-compatibility/README.md)。
- 初次全量归档检查49/49通过，17个无关应用目录所有文件及两份原APK保持原样；补运行结果后最终全量复核仍49/49通过，报告归档 `archive-check.json`。独立审查未发现阻塞性代码/文案问题。
