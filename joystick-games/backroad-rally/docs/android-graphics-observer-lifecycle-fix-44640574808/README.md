# Correct the separate Observer's creation timing

The original diagnostic run `44640574808` at `6d91b690e4b21bb7af578b7eec4dbfe3eea4ccbd` failed before SDK input: `Startup console was not attached before load`. Its first console event was `No WebView in onActivityCreated`. The original failed report and immutable export `aac73b61f55e7b509fa8d1718646c7f407f492ca` remain unchanged; this is an Observer failure, not a new game failure or a successful visual diagnosis.

Android 16/API 36 framework source explains the ordering. `Activity.onCreate` dispatches `onActivityCreated` from its own body. The frozen target calls `super.onCreate` first, then constructs its WebView and calls `setContentView`. Thus that application callback runs too early to find the WebView. `Instrumentation.callActivityOnCreate(Activity, Bundle)` synchronously calls the complete `Activity.performCreate` and returns; the later `ActivityThread.handleStartActivity` invokes `performStart`. The original non-persistable activity uses this two-argument creation path.

The only changed diagnostic source is `GraphicsObserver.java`. Its lifecycle callback still records the created state, but no longer attaches the console. The new instrumentation override first delegates to `super.callActivityOnCreate`, then synchronously calls the existing target-only attachment before the target's `onStart` starts the room and posts `loadUrl`.
