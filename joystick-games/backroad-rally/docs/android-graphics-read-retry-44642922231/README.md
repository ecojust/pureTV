# Read-only graphics transport recovery within the original menu deadline

The original v2 diagnostic (`44642922231`, source `0415846f`) attached the startup console and observed 29 selected menu steps. At original step 33, one normal SDK A tap received both ACKs, but a single graphics GET closed after 10.003 seconds. A later, new final GET observed the actual Finland introduction. The original failure is preserved; it does not reproduce the black race scene.

Only the separate diagnostic driver and its existing Python test file change. Menu reads allow up to three new GETs, fifteen seconds per request and forty-five seconds per observation, all capped by the unchanged step deadline. HTTP/JSON/body-budget/game errors remain hard failures. SDK taps, release/ACK checks, predicates, the 240-second start budget, and two fresh-poll confirmations are unchanged. There is no cached-success fallback or input replay.

The first draft passed 15 tests but was rejected by independent review: its socket idle timeout did not bound a slowly dripping response. A real HTTP counterexample exceeded a 25 ms step budget and published the expired body to `last`. That draft, its log/freeze and the review counterexample remain intact. They are not proof of a bounded total deadline.

The final draft uses a guarded Linux main-thread `SIGALRM` deadline around headers, body reading, JSON parsing and hashing. It refuses an existing timer or another thread, always restores the prior handler and clears its own timer, and checks the deadline before publishing a valid body. There is no background reader that can write a late result. The default non-menu HTTP path remains unchanged.

The exact `0415846f3b3e3fc11f79e08d25050affdf750435` parent plus only these two overlays passed 18 tests. All imports and the existing two v7 fixtures came from that parent, excluding concurrent Windows changes. Real loopback cases cover connection drop then fresh JSON, three-attempt exhaustion, delayed response, slow headers, slow body, unchanged old state after timeout, hard HTTP/JSON/budget/game failures, and signal cleanup/ownership. A delayed JSON parse is also interrupted. The slow-header/body assertions allow scheduler cleanup overhead and require return within 100 ms for a 25 ms budget; the alarm is armed to the actual absolute deadline. This is host-side transport validation, not a new Android or graphics result.
