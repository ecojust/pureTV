# 浏览器验收

在 Linux Chromium 的 Mesa 软件 GPU 上，以 [browser.py](../../tests/browser.py) 从标题页选择第二位车手 Zippy，开进棕榈湾赛道。960×540 使用键盘；1280×720 使用单席原生桥接帧模拟，按住转向、油门、漂移与回看，断开时暂停，重连后松开并重新按 START 继续。两组赛钟与位置在暂停时保持静止，比赛中八辆卡丁车和 HUD 正常绘制，所有网络请求均来自本地资源。逐场速度和位置见 [browser.json](browser.json)。

赛中画面使用游戏脚本 SHA-256 `dc7b601bdf13a603fdbb2a63fde981ac4c4eac541626da3250fd734473d0e99c`。两次赛中截屏的速度表均为 61 km/h。连接卡位于右侧排名与时速表之间。赛道未完成全程；本组脚本没有操作实体电视、手机或 ESP32。[960×540 实况](../../thumb.png) · [1280×720 实况](race-1280.png) · [1280×720 选手画面](select-1280.png)

首轮 960×540 选手截图中，难度和圈数占位但不可见。随后独立的菜单测试复现了两个选项可通过键盘修改但 `is_visible()` 为假的问题。该轮 CSS 的 SHA-256 为 `7a7d0c45576aeb2721853d56ec313ed6d0e1e9110a3cf23023493ce93518147f`。[修复前截图](select-960.png)

软件渲染启动的探索测试中，在多个 Chromium 实例共用两个 CPU 核时，原始 3D 标题演示等待时间过长。中途停止的测试没有计入通过结果。软件 GPU 现在直接显示车手菜单背景，在正式开赛时创建赛道。

修复选项的可见性过渡后，重新构建及 `build:check` 通过。使用最终 CSS（SHA-256 `de1d9a68143703b0531bf7dca90670ef9c23880010265cff61dca272ae3a9ed6`）在小尺寸窗口用方向键切换到 150cc 和 1 圈，两行文字和当前焦点均可见。游戏脚本与上述赛中记录一致。[最终画面](options-960.png) · [执行脚本](../../tests/menu.py)
