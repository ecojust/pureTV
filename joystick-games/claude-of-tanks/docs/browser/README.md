# 克劳德坦克 0.1.0 试玩记录

2026 年 11 月 27 日，在 Linux Chromium 156.0.8078.79 中加载 APK 内的游戏资源。从中文车库选择默认车辆，在本地“翠绿山谷”开局。车库在 28.59 秒后出现，从按 START 至倒计时结束、可以驾驶共 55.11 秒。两种窗口尺寸均呈现了坦克、地形和战斗界面。期间站外请求、失败的本地响应、页面异常与控制台错误均为零。[960 × 540 实玩截图](playing-960.png) · [1280 × 720 实玩截图](playing-1280.png) · [194 秒实玩录像](gameplay.mp4)

## 输入与暂停

键盘 W 使车辆移动了 1.96 个地图单位。JoystickClient 经本机 TCP 发送前进和左转，位置、速度和朝向均有变化。随后通过浏览器 Gamepad API 模拟标准手柄摇杆，同样改变了车身朝向。按 START 暂停后观察 400 毫秒，位置、朝向和对战时间保持稳定。驾驶中断开 TCP 会清除按住的方向键并暂停，重连后再按 START 可恢复对局。[暂停画面](paused.png) · [输入与游戏状态报告](report.json) · [复现脚本](../../qa/play.py)

手机手柄另以两个独立 Chromium 和 Game Kit 的 Java 局域网房间服务验证。ZXing 从车库的完整截图读出二维码，触屏模拟浏览器打开手机手柄页，发送 START、前进、左转。游戏内速度由 0.007 升至 0.273，车身转过 0.086 弧度，断开手机连接后方向输入释放。实体手机、电视和物理手柄尚未实测。[扫码车库](../phone-controller/menu.png) · [手机操控后的画面](../phone-controller/playing.png) · [房间与触屏验收记录](../phone-controller/report.json)

## 软件渲染与帧率

本次 Chromium 使用 SwiftShader，软件渲染档将 3D 缓冲限制为 720 × 405，减少草木、远景网格、阴影和后期效果，地面仍使用原地图纹理与地形。正常硬件 GPU 使用原作画质设置。切至 1280 × 720 并取得有效画面后，游戏主循环在 11.158 秒内更新 6 帧，短时平均约 0.54 帧/秒。测量范围限于此软件环境的单段实玩，未测实体电视帧率。录像按合成画面时间戳编码为 640 × 360。[采样数据](report.json)

## 资源与复现

受测本地未签名 APK 中的 489 个游戏文件逐一匹配冻结提交 `58646c1ec3bcfc31c31b7c11a3cf44df2d47db8e`，包中另有 5 个 Game Kit 配置及手柄文件。正式签名 APK 含有同样的 494 个资源，每个文件均与这次浏览器实玩所用包一致。游戏卡片使用较早中文候选版在同一地图驾驶时的实拍，经裁剪缩放至 640 × 360。浏览器资源树、截图与录像的摘要可在校验清单核对。[资源校验清单](../source-check.json) · [封面原图](../gameplay-960.png) · [签名流程和模拟器报告](https://github.com/ecojust/pureTV/actions/runs/46010919467)

首次 Android TV API 36 模拟器验收中，默认端口场景进入中文车库后，观察器在采集截图时断开；占用默认端口的场景在 150 秒内未取得车库状态。两项均未完成 Android 实玩验证。[签名包记录](../releases/0.1.0/android.json)

在游戏目录运行 `python qa/play.py /tmp/tanks-qa --apk /path/to/claude-of-tanks.apk` 可重新采集。环境使用 Chromium、FFmpeg、Python Playwright、Pillow 和仓库的手柄 SDK。
