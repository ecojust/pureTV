# 克劳德坦克普通 Chromium 驾驶验收

2026 年 11 月 27 日，Linux 上的 Chromium 156.0.8078.79 以普通进程启动，由 Playwright 通过本机 CDP 连接。车库与驾驶画面均实测 `navigator.webdriver === false`，WebGL2 报告 SwiftShader 软件渲染器。中文车库在 61.99 秒后出现，用局域网手柄 SDK 按 START 后，经过 62.09 秒可以驾驶。两种窗口尺寸都看到车辆、山地和中文 HUD。每次截图前都等待有效游戏帧，并检查画面中心的颜色方差。[车库](garage.png) · [960 × 540 驾驶画面](playing-960.png) · [1280 × 720 驾驶画面](playing-1280.png)

## 驾驶和停车

键盘 W 使车辆移动 1.06 个地图单位。JoystickClient 经本机真实 TCP 连接发送前进、左转，车辆位置与朝向均改变。浏览器 Gamepad API 的模拟标准手柄摇杆也能转向。录像可见车辆先加速再制动。同步采集的游戏速度达到 2.25，按 B 后降至 0.23。START 暂停后，观察 400 毫秒确认位置、朝向、速度和对局时间稳定。按住前进键时断开手柄会释放输入并暂停，重新连接后可按 START 恢复。[41.7 秒驾驶与制动录像](gameplay.mp4) · [暂停截图](paused.png) · [输入和渲染报告](report.json)

另用同一版本 APK 的 Java 房间服务及两个独立普通 Chromium，验证手机扫码后能开始、前进、左转和断开。该次首启遇到 SwiftShader 图形设备重置，点击画面上的重新加载按钮后完成验证。实体手机尚未实测。[手机扫码及驾驶报告](../phone-controller/report.json)

## 软件渲染

车库和对局的绘图缓冲均为 720 × 405，两个阶段的软件渲染诊断都没有重新启用动态阴影。在 1280 × 720 窗口中，游戏主循环在 10.261 秒内更新 5 帧，观测值为 0.49 帧/秒。这一结果来自软件 GPU。本轮没有测量实体电视的硬件 GPU 帧率。[采样记录](report.json)

另用两个干净的普通 Chromium 配置，对照首次发布的 `58646c1` 和仅修复阴影的 `805e2f4`。在同为 960 × 540 的车库中，前者 23.59 秒更新 5 帧，并触发 4 次额外 GPU 读回、198 次着色器编译，后者 21.22 秒更新 23 帧，额外读回和编译均为零。最终实玩版本 `1a532f8` 还修复了启动时对已移除编辑器的访问。[两次车库采样](garage-comparison.json)

## 资源与复现

实玩取自冻结提交 `1a532f8fe4b0cb4ff2ce6a838c8722ea91d87239` 的 489 个游戏文件。测试将这些文件放进本地 ZIP，由管理器测试服务载入，整轮站外请求、本地 HTTP 错误、页面异常与控制台错误均为零。逐文件核对确认 Android 未签名 APK 包含全部 489 个文件，另有 5 个 Game Kit 宿主文件。正式签名 APK 的 494 项资源也逐项匹配上述未签名 APK，签名包 SHA-256 为 `989695d339996985a629adb42b0bccbbc166ffbf88a713053404d1df0c7118b5`。[资源和录像校验清单](source-check.json) · [历史版本记录](../../../../browser/README.md)

从游戏目录执行 `python qa/play.py /tmp/tanks-qa --apk /path/to/claude-of-tanks.apk` 可直接测试包内资源。环境需要 Chromium、FFmpeg、Python Playwright 和 Pillow，手柄端使用仓库自带 SDK。录像使用合成帧时间戳编码，分辨率为 640 × 360。[实玩脚本](../../../../../qa/play.py)
