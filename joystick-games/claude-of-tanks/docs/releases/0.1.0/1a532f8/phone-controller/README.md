# 手机扫码与图形恢复实测

本轮使用冻结提交 `1a532f8` 构建的 APK 资源与 Game Kit 的 Java 局域网房间。电视页面和触屏手柄分别打开于独立 Chromium 156，两端的 `navigator.webdriver` 均为 `false`。测试机使用 Linux 和 SwiftShader 软件渲染。实体电视与手机尚待实测。

第一次打开时，电视页面显示图形设备已重置，主画布已丢失 WebGL 上下文，二维码被错误对话框盖住。点击游戏的 **Reload** 后，中文车库和二维码恢复。ZXing 从电视完整截图识别出房间地址，手机随后连接成功。[首次故障画面](graphics-reset.png) · [恢复后的扫码页面](menu.png)

用手机按 **START** 进入战场，按 **上** 后速度从 0.00594 增至 0.09983，按 **左** 后车身方向从 0.10527 转至 0.12689 弧度。断开手机连接后，游戏释放了方向输入。[手机操控后的战场](playing.png) · [扫码、速度与断开记录](report.json)

在同一软件渲染环境单独冷启动复查时，Chromium 的 GPU 子进程异常退出。三份对应时刻的 Crashpad 转储均将异常线程标为 `GpuWatchdog`。一次复查观察到游戏自动重载，随后电视仍显示重置对话框，150 秒内未能扫码。上述结果与已安装 Android APK 的独立模拟器测试分别记录。[软件渲染复查](report.json) · [Android 安装验收](../../android.json)
